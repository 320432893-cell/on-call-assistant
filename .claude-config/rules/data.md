# 数据处理规则强制版

## 文件定位
- 本文件只包含**强制阻断级**规则，覆盖 Excel/CSV/JSON 数据处理场景
- 违反即阻断，无阻断条件的陈述句已删除
- SQL 相关规则待有 SQL 项目时单独添加

## 1. 数据归一化规则【强制】

### 触发条件
执行数据合并、比对、关联操作前

### 必须输出
```
[数据归一化自检]
- 关联键字段（用于合并/比对的字段）：________________
- 关联键归一化（每项必须给出样本前后对比，不能只勾选）：
  | 项 | 原值样本 | 归一化后样本 |
  |----|---------|-------------|
  | 空白（strip） |  |  |
  | 大小写 |  |  |
  | 单位/格式 |  |  |
- 数值字段精度统一（如存在）：
  - 字段名：________ 原精度 ________ → 统一精度 ________
- 缺失值策略：□ 填充（值：____）□ 标记（标志列：____）□ 丢弃
```

### 阻断条件
- 关联键样本前后对比为空 → **[阻断] 必须给出关联键的归一化前后真实样本值**
- 关联键归一化未声明 → **[阻断] 至少声明 strip+大小写+格式三项**
- 多文件合并/比对未标识关联键 → **[阻断] 先声明关联键再合并**

## 2. 幂等设计规则【强制】

### 触发条件
新增/修改数据写入逻辑（生成记录、写入文件、更新状态）

### 必须输出
```
[幂等自检]
- 操作类型：新增记录 / 更新记录 / 生成文件 / 其他
- 重复执行场景：
  □ 手动重跑
  □ 程序崩溃重启后自动重试
  □ 定时任务重叠
  □ 其他：________
- 幂等策略（至少一种）：
  □ 唯一键约束（数据库/文件名/记录ID）
  □ 存在性检查（写前先查）
  □ 覆盖写（重复执行结果一致）
  □ 增量标记（只处理未处理数据）
  □ 其他：________
- 重复执行测试结果：□ 已通过 □ 未测试
```

### 阻断条件
- 无幂等策略勾选 → **[阻断] 数据写入必须设计幂等，请补充策略**
- 未测试重复执行 → **[阻断] 请测试重复执行场景，确认无重复数据/副作用**

## 3. 中间状态保存规则【强制】

### 触发条件
实现长时间数据处理（预计执行时间 > 30 秒，或处理数据量 > 10 万行）

### 必须输出
```
[中间状态自检]
- 预计执行时间：________ 秒
- 处理数据量：________ 行/条
- 检查点策略：参考 `web-automation.md` § 2 会话保活的检查点设计；本场景需要：
  □ 每 N 条记录保存（N = ________）
  □ 每阶段完成后保存（阶段：________）
  □ 按时间间隔保存（间隔：________ 秒/分钟）
- 状态保存位置：文件路径 ________ / 数据库表 ________
- 状态内容：
  □ 当前进度（已处理数/总数）
  □ 已处理项标识（如ID列表、时间戳）
  □ 处理上下文（如当前阶段、配置参数）
- 恢复机制：□ 支持从检查点继续 □ 仅记录进度
```

### 阻断条件
- 长时间操作无检查点策略 → **[阻断] 长时间处理必须定期保存中间状态，请设计检查点**
- 状态保存位置未指定 → **[阻断] 请指定状态保存位置**
- 恢复机制未支持且未说明原因 → **[阻断] 建议支持从检查点继续，若不支持请说明原因**

## 4. Excel 写入冲突检查规则【强制】

### 触发条件
向已存在的 Excel 文件写入数据（覆盖、追加、修改）

### 必须输出
```
[Excel 写入冲突自检]
- 目标文件：________
- 文件是否存在：□ 是 □ 否
- 若存在：
  □ 已确认目标 sheet/区域无人工修改
  □ 已备份原文件（路径：________）
  □ 已记录写入时间/版本标记
- 写入策略：
  □ 覆盖写入（整文件替换）
  □ 追加写入（在末尾添加）
  □ 修改写入（更新特定区域）
- 冲突检测机制：
  □ 文件哈希校验（写入前 vs 写入后）
  □ 修改时间戳检查
  □ 版本号比对
  □ 无（风险确认：________）
```

### 阻断条件
- 文件存在但未确认无人工修改 → **[阻断] 请确认目标文件自上次写入后未被人工修改**
- 覆盖写入且无备份 → **[阻断] 覆盖写入前必须备份原文件**

## 5. 脏数据处理规则【强制】

### 触发条件
处理可能存在脏数据的数据源（用户输入、外部文件、爬虫结果、第三方接口返回）

> 与 `code.md` § 4 异常分层捕获 的区别:本规则处理"数据合法但内容脏"(空值/类型不符/格式错/重复),异常处理处理"代码运行抛异常"。

### 必须输出
```
[脏数据处理自检]
- 数据源：________
- 脏数据场景识别：
  □ 空值/缺失值处理策略：________
  □ 类型不匹配处理策略：________
  □ 格式错误处理策略：________
  □ 重复数据处理策略：________
- 清洗日志：□ 记录脏数据位置/原因 □ 不记录
- 失败数据处理：
  □ 跳过并记录
  □ 使用默认值
  □ 终止处理
  □ 其他：________
- 数据质量报告：□ 输出清洗统计 □ 不输出
```

### 阻断条件
- 脏数据场景识别未覆盖主要风险 → **[阻断] 请识别至少3种脏数据场景并制定处理策略**
- 失败数据处理策略未明确 → **[阻断] 请明确脏数据是跳过/默认/终止处理**

## 6. 数据契约规则【强制】

### 触发条件
处理新数据源前（新接入的 Excel / CSV / JSON / 数据库表 / 接口返回）

### 必须输出
```
[数据契约自检]
- 数据源：________________
- 样本截图/输出位置：________（必须粘贴 ≥ 5 条真实样本，不能只勾"已读取"）
- 关键字段契约（仅列对业务关键的字段，不要列完）：
  | 字段名 | 类型 | 是否可空 | 实际样本值 |
  |--------|------|---------|-----------|
- 关键字段必填项（任一适用即必填）：
  □ 主键/唯一标识：________
  □ 时间字段格式：________（如 "2026-05-17" 或 "2026/5/17 14:30"）
  □ 金额/数值字段单位 + 精度：单位 ________ / 精度 ________
- 编码与时区（仅当涉及）：
  □ 文本编码：________（UTF-8 / GBK）
  □ 时区：________（UTC / 本地 / 字段自带）
```

### 阻断条件
- 未粘贴 ≥ 5 条真实样本就开始写处理代码 → **[阻断] 先读真实样本观察实际结构**
- 关键字段实际样本值列为空 → **[阻断] 必须给出真实样本值，不接受"待补充"**
- 时间字段无格式声明 → **[阻断] 明确日期格式（避免月日颠倒等）**
- 金额字段无单位+精度声明 → **[阻断] 明确单位（元/分/美元）和小数位数**

## 7. 完整性对账规则【强制】

### 触发条件
执行数据合并、转换、过滤、写出后

### 必须输出
```
[完整性对账自检]
- 处理类型：□ 合并 □ 转换 □ 过滤 □ 写出
- 处理前指标：
  □ 行数：________
  □ 关键字段去重数：________
  □ 数值总和（如适用）：________
  □ 文件大小：________ KB
- 处理后指标：
  □ 行数：________
  □ 关键字段去重数：________
  □ 数值总和（如适用）：________
  □ 文件大小：________ KB
- 差异说明：
  □ 行数差异 = 已识别异常数（如 X 行重复/Y 行空值）
  □ 总和差异 = 已识别原因（汇率/单位转换等）
- 异常退出策略：差异无法解释时 □ 终止处理 □ 告警人工 □ 其他：____
```

### 阻断条件
- 处理后未输出前后指标对比 → **[阻断] 必须输出对账指标**
- 行数差异无法用"已识别异常"解释 → **[阻断] 终止处理，排查静默丢数据**
- 总和差异无法解释 → **[阻断] 排查类型转换/编码导致的数据损坏**

## 8. 多步写入失败模式【强制】

### 触发条件
- 多步写入操作（≥ 2 次 IO/DB/外部调用）
- 状态变更链（A 改完改 B 再改 C）

### 必须输出
```
[失败模式自检]
- 操作链：步骤 1 ____ → 步骤 2 ____ → 步骤 3 ____
- 原子性边界：哪几步必须一起成败：________________
- 部分成功处理（每步失败时的策略）：
  | 步骤 | 失败时已完成什么 | 处理策略 |
  |------|-----------------|---------|
  |      |                 | □ 回滚 □ 补偿 □ 标记重试 □ 告警人工 |
- 可观测性：每个失败点是否能定位（日志/状态码）□ 是 □ 否
- 重试幂等性：步骤是否可安全重试（参考 § 2 幂等设计）□ 是 □ 否
```

### 阻断条件
- ≥ 2 步写入未声明原子性边界 → **[阻断] 明确哪几步必须一起成败**
- 中间步骤失败无处理策略 → **[阻断] 每步失败都要有处理策略**
- 步骤不幂等且无去重键 → **[阻断] 加去重键或改幂等设计（参考 § 2）**

> FastAPI/数据库事务边界由 `backend.md` § 4 阻断；本规则覆盖通用多步写入（含文件、外部 API、跨服务）。

## 附录A：推荐级规则（完成后复查）

以下规则不触发阻断，代码完成后自查：

- **引擎选择**：大数据（>100万行）优先 polars/duckdb，pandas 限小数据（<10万行）
- **性能优化**：向量化 > itertuples > apply > iterrows
- **批量写入**：先内存缓存再批量写入，禁止循环内逐行写
- **空间-时间权衡**：频繁查询用索引，重复计算用缓存，大数据用流式
