# 用户交互语义规则

## 1. 文件定位

- 本文件管用户和软件如何交互，不绑定 GUI、Web、CLI 或具体框架。
- 本文件适用于桌面 GUI、Web 前端、本地工具、管理后台、CLI/TUI、调试辅助界面。
- 本文件不是交互细节百科；核心是用共性维度推导具体交互，少量例子只用于激活联想。
- GUI 场景命中本文件时允许较高推理压力，因为按钮、窗口、关闭、日志、F12 等细节不应都由用户逐项描述。

核心问题：用户在这个界面里要完成什么动作？过程中哪里可能困惑、误操作、等待、失败、后悔、需要求助？

---

## 2. 触发分级

### 2.1 不触发或轻触发

命中场景：

- 纯后端逻辑、小数据处理、小路径 bug。
- 不改变用户可见界面、提示、按钮、窗口、命令输出。
- 用户明确只要内部实现修复。

AI 行为：

- 不加载本文件或只做轻量判断。
- 不把小逻辑修复升级成 UX 设计。

### 2.2 常规触发

命中场景：

- 新建或修改用户可见界面、按钮、表单、弹窗、菜单、快捷键、窗口、结果区、日志区。
- 新增错误提示、空状态、加载状态、成功/失败反馈。
- 新增关闭、取消、停止、重试、导出、复制等用户动作。
- 用户提到“交互”“体验”“好用”“按钮”“窗口”“弹窗”“F12”“调试入口”。

AI 行为：

- 用交互风险维度做轻量判断。
- 给出默认交互假设，必要时请用户拍板。
- 不要求每次输出长清单。

### 2.3 GUI 交互地基：允许高压默认

命中场景：

- 桌面 GUI、本地工具、批处理界面、文件处理界面。
- 有后台任务、长时间运行、日志输出、文件输入输出、用户协作排障。
- 有危险操作、不可逆操作、未保存状态、运行中关闭。

AI 行为：

- 不等待用户逐项描述按钮、窗口、日志、错误、F12 等细节，主动按默认交互地基补齐。
- 修改前用短列表列出默认假设，让用户拍板。
- 复杂 GUI / 内部工具 / 批处理工具 / 文件处理工具 / 有后台任务的工具，必须有 F12 或等价诊断入口；没有时必须说明替代取证方式。

示例话术：

```md
我默认按这个交互地基做：
- 主窗口可调节，日志/结果可滚动可复制
- 有耗时任务则提供停止按钮和运行中禁用
- 有后台任务则提供 F12 或等价诊断入口
- 危险操作二次确认，默认焦点在取消
- 错误提示用业务语言，详情进诊断面板/日志
```

## 3. 交互风险维度

AI 遇到用户可见交互时，优先从以下维度推导，而不是试图枚举所有规则。

### 3.1 目标可见

- 用户应知道当前能做什么、下一步是什么、当前处于什么状态。
- 空状态、加载中、无匹配、无权限、失败状态不能留白。
- 禁用按钮如果用户可能困惑，应有原因或附近状态提示。

### 3.2 动作可控

- 用户发起动作后，不应失去控制。
- 耗时任务应有运行反馈；可中止任务应提供停止/取消入口。
- 重复点击、重复提交、重复启动同一任务要有防护。

### 3.3 后果可预期

- 用户点之前应知道会发生什么，点之后知道发生了什么。
- 删除、覆盖、清空、重置、批量操作、终止任务等危险操作要说明对象、影响范围、是否可逆。
- 危险确认框默认焦点优先在取消或安全选项。

### 3.4 失败可恢复

- 失败后用户应知道原因、影响范围、下一步能做什么。
- 可恢复错误提供重试、重新选择、复制详情、打开日志、返回上一步等路径。
- 用户主动停止和系统失败必须区分。

### 3.5 信息可取证

- 用户应能把问题说清楚，AI/开发者能接着查。
- 错误、日志、路径、任务 ID、trace_id、配置摘要、版本信息等排查信息尽量可复制。
- 诊断信息不得暴露密钥、token、完整隐私数据。

### 3.6 界面可承载

- 内容不能因为窗口、长文本、长路径、数据量、表格列太多而不可用。
- 主工作窗口、日志区、结果区、表格/列表区默认应可调整大小、滚动、换行、截断或展开。
- 短表单、确认框、简单设置框可以固定尺寸。

### 3.7 成本可匹配

- 交互复杂度要和任务价值匹配。
- 小工具不强制完整调试中心；复杂批处理、文件处理、内部工具必须考虑诊断入口。
- 简单关闭不弹确认；存在运行中任务、未保存修改、未完成输出或不可恢复状态时才确认。

### 3.8 习惯可尊重

- 遵守平台、浏览器、框架和用户已有习惯，不发明反直觉交互。
- Web 不默认劫持浏览器 F12。
- 桌面 GUI 可优先考虑 F12 诊断入口。
- `Ctrl+C` 复制、`Esc` 关闭弹窗、`Enter` 提交要按场景谨慎使用；危险操作不应被误触发。

## 4. 按钮与基础控件默认

- 一个界面里尽量只有一个最突出的主操作。
- 按钮文案说动作，不说抽象名词；例如“导出结果”优于“确定”。
- 危险按钮应和普通按钮区分，不能默认聚焦，必须有确认或撤销策略。
- 耗时按钮点击后立即禁用或进入运行态，避免重复提交。
- 运行中显示停止/取消入口；停止后的状态与失败分开。
- 多按钮顺序遵守平台习惯和项目现有风格。
- 关闭窗口时，只有存在运行中任务、未保存修改、未完成输出或不可恢复状态，才触发确认。
- 结果、日志、错误、路径等文本尽量可复制。

---

## 5. F12 / 诊断入口

- 复杂 GUI、内部工具、批处理工具、文件处理工具、有后台任务的工具，必须考虑 F12 或等价诊断入口。
- 桌面 GUI 默认优先考虑 F12 打开/关闭诊断面板。
- Web 页面不默认劫持浏览器 F12；需要诊断入口时，优先使用页面内开关、非冲突快捷键或开发模式开关。
- CLI/TUI 使用 `--debug`、`--verbose`、`--diagnose` 或等价命令表达同类能力。
- 后台服务用 health/version、trace_id、日志和诊断命令表达同类能力，不叫 F12。

最低可用诊断信息：

- 当前任务状态。
- 最近错误。
- 日志路径。
- 当前配置摘要。
- 输入/输出路径。
- 版本信息。
- 可复制诊断文本。

安全边界：

- 不展示密钥、token、密码、完整隐私数据。
- 配置摘要应脱敏。
- 诊断入口不能成为普通用户绕过权限或读取敏感信息的入口。

## 6. 20% 示例库

以下不是穷尽清单，只是帮助 AI 联想。遇到新场景时按交互风险维度推导，不得因为清单没有写就忽略。

- 关闭确认：仅在运行中任务、未保存、未完成输出、不可恢复状态时确认。
- 窗口承载：主工作区、日志、表格、结果区默认可调节或可滚动。
- F12：桌面复杂工具优先考虑诊断面板；Web 不默认劫持浏览器 F12。
- 错误可复制：错误、日志、路径、任务 ID 尽量能复制。
- 空状态：无数据、无匹配、无权限、加载失败不能留白。
- 危险操作：删除、覆盖、清空、重置、批量操作要说明对象和后果。
- 耗时任务：有反馈，可中止，停止和失败分开。
- 长内容：长路径、长日志、大表格不能撑爆界面。
- 禁用按钮：如果用户可能不知道为什么禁用，要给原因。
- 默认焦点：危险确认默认落在取消或安全选项。

## 7. AI 与用户协作设计

- 复杂交互必须和用户讨论，因为真实用户习惯、业务优先级和容忍成本 AI 猜不全。
- AI 应先给一版默认交互假设，减少用户逐项描述成本。
- 用户拍板后按拍板执行，不反复争辩；但保留风险记录。
- 如果 AI 认为用户要求会制造误操作、误删、卡死、排查困难或维护负担，必须明确反对并说明理由。

---

## 8. 工具与验证

- 交互规则多数不能交给 lint，需要 AI 和用户共同判断。
- 能工具化的部分优先工具化：单元测试测状态转换，端到端测试测关键路径，截图/手动验证检查窗口承载。
- GUI/Web 交互改动完成后，至少说明验证过哪些用户路径；无法验证时说明剩余风险。
