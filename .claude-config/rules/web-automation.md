# Web自动化规则强制版（Playwright）

## 文件定位
- 本文件只包含**强制阻断级**规则，覆盖企业管理系统、税务外汇等复杂场景
- 违反即阻断，无阻断条件的陈述句已删除

## 1. 验证码策略规则【强制】

### 触发条件
目标网站存在验证码（图片验证码、滑块、短信验证等）

### 必须输出
```
[验证码策略自检]
- 验证码类型：□ 图片验证码 □ 滑块验证 □ 短信验证 □ 其他：________
- 处理策略（必须选一）：
  □ 人工介入（暂停脚本，用户手动输入后继续）
  □ 第三方打码服务（服务名称：________）
  □ 绕过策略（说明：________）
  □ 验证码识别模型（模型/服务：________）
- 策略实现检查：
  □ 验证码出现检测逻辑
  □ 暂停/等待机制
  □ 用户输入接收方式
  □ 失败处理（验证码错误重试/终止）
- 未实现能否继续：□ 能（有兜底） □ 否（阻断）
```

### 阻断条件
- 无明确处理策略 → **[阻断] 存在验证码但未明确处理策略，请选择人工介入/第三方服务/绕过策略后继续**
- 策略未实现且无兜底 → **[阻断] 验证码处理策略未实现，请实现或提供兜底方案**

## 2. 会话保活规则【强制】

### 触发条件（满足任一即触发）
- 目标系统属于强登录态类（税务 / 外汇 / 企业管理系统 / 银行）
- 用户声明任务为"长任务/批量任务"
- 任务包含循环抓取 ≥ 50 次页面操作（可机械计数）
- 任务设计中包含"中途登录态丢失需处理"的需求

### 必须输出
```
[会话保活自检]
- 系统类型：□ 税务 □ 外汇 □ 企业管理系统 □ 其他
- 登录态检测机制：
  □ 定期心跳（间隔：________秒/分钟）
  □ 操作前检测登录态
  □ 响应特征检测（如跳转登录页、特定错误码）
- 会话过期处理：
  □ 自动重登录（需保存凭据/验证码处理：________）
  □ 暂停通知用户
  □ 保存进度后退出
- 检查点保存：
  □ 定期保存操作进度（间隔：________）
  □ 支持从检查点恢复
- 资源隔离与清理：
  □ 每次运行独立 user-data-dir（不共用浏览器配置）
  □ 运行结束清理临时目录 / 关闭 context
  □ 异常退出有兜底清理（atexit / try-finally）
```

### 阻断条件
- 无登录态检测机制 → **[阻断] 长时间操作必须有登录态检测机制**
- 无会话过期处理策略 → **[阻断] 请明确会话过期后的处理策略（重登录/暂停/保存退出）**
- 多次运行复用同一 user-data-dir 且无清理 → **[阻断] 各次运行隔离 user-data-dir 或显式清理**

## 5. 样式修改与事件注入规则【强制】

### 触发条件
原生Playwright操作无法触发目标行为，需要样式修改或JS注入

### 必须输出
```
[样式/事件注入自检]
- 目标行为：________________
- 原生操作尝试：
  □ select_option（下拉选择）
  □ fill（输入）
  □ click（点击）
  □ 其他：________
- 原生操作结果：□ 成功 □ 失败（原因：________）
- 注入方案：
  □ CSS样式修改：page.add_style_tag(content="________")
  □ JS事件触发：page.evaluate("document.querySelector('...').dispatchEvent(new Event('change'))")
  □ 强制赋值：page.evaluate("document.querySelector('...').value = '...'")
- 注入后验证：
  □ 目标行为已触发
  □ 页面状态已更新
  □ 表单校验通过
```

### 阻断条件
- 原生操作未尝试直接注入 → **[阻断] 必须先尝试原生操作，失败后才可使用注入方案**
- 注入后未验证效果 → **[阻断] 注入后必须验证目标行为已触发且页面状态已更新**

## 8. 执行时间检查规则【强制】

### 触发条件
Web自动化操作中涉及页面加载、数据抓取、表单提交等耗时操作

### 必须输出
```
[执行时间检查自检]
- 操作类型：□ 页面加载 □ 数据抓取 □ 表单提交 □ 等待元素 □ 批量循环
- 预计耗时：________ 秒
- 时间阈值检查：
  □ ≤ 5秒：正常等待，无需额外处理
  □ > 5秒且≤ 30秒：需有进度指示或说明原因
  □ > 30秒：必须有进度反馈或分阶段执行
- 进度反馈机制：
  □ 阶段文字提示（如"正在抓取第3/10页"）
  □ 百分比进度
  □ 日志流输出
  □ 不适用（有明确截止时间）
- 单次循环耗时监控：
  □ 已记录单次操作耗时（>=100次循环时）
  □ 平均耗时：________ 秒，预估总耗时：________
```

### 阻断条件
- 预计>30秒无进度反馈 → **[阻断] 长时间操作必须有进度反馈机制**
- 批量操作循环>=100次未记录单次耗时 → **[阻断] 大规模循环必须监控单次耗时，用于预估进度**
- 实际执行超预计2倍未处理 → **[阻断] 超时异常需报错或降级处理**

## 10. 失败现场取证规则【强制】

### 触发条件
关键操作（登录 / 提交 / 跳转 / 数据抓取 / 文件下载）失败时

### 必须输出
```
[失败现场取证自检]
- 取证触发点：哪些操作失败时自动取证：________________
- 自动取证内容：
  □ 截图（page.screenshot，含全屏 full_page=True）
  □ 当前 HTML（page.content）
  □ Console log（page.on("console")）
  □ Network 最近 N 条（含失败请求）
  □ 当前 URL
  □ 当前时间戳
- 取证存储：
  □ 保存路径：________ / 错误日志路径：________
  □ 文件名包含时间戳+操作标识，避免覆盖
- 与 § 7 用户取证的关系：
  □ 本规则是 § 7 的前置（自动取证够用就不打扰用户）
  □ 自动取证后仍无法定位 → 升级到 § 7 用户 F12 取证
```

### 阻断条件
- 关键操作无失败自动取证 → **[阻断] 至少保存截图 + HTML**
- 取证文件覆盖（文件名不含时间戳）→ **[阻断] 文件名加时间戳**
- 直接跳到用户取证 → **[阻断] 先尝试本规则的自动取证**

## 附录A：iframe多层嵌套参考方案

### 诊断脚本
```python
# 枚举所有frames
frames_info = page.evaluate("""
  () => Array.from(document.querySelectorAll('iframe')).map(f => ({
    id: f.id,
    name: f.name,
    src: f.src,
    parent: f.parentElement?.tagName
  }))
""")
```

## 附录C：推荐级规则（完成后复查）

- **人类行为模拟**：逐字输入（`type`参数设置延迟）、鼠标移动轨迹、随机等待，对抗反爬检测
- **文件上传**：区分系统弹窗（`input.set_files`）和拖拽上传，提前确认上传方式
- **数据导出/下载**：等待文件生成、处理下载弹窗、确认文件完整写入
- **翻页策略**：检查onclick/nextPage/form.submit链路，优先执行原生JS或submit
- **数据提取**：表格优先`evaluate`一次性提取整页，禁止逐单元格locator读取
