- 本文件只包含**强制阻断级**规则,且**只保留机器查不到的"思想范式"**
- 机器可查的规则(函数大小/类型/格式/import/print)交给工具链(ruff/mypy/import-linter,见附录 B)
- 强制规则数 ≤ 10 条(workflow.md § 2.3.2 上限)
- 跨文件职责分工:
  - 分层依赖、外部调用边界 → `architecture.md`
  - 多步写入失败模式、数据契约、幂等、对账 → `data.md`
  - GUI → `gui.md`、前端 → `frontend.md`、打包 → `package.md`
  - Web 自动化 → `web-automation.md`、FastAPI 后端 → `backend.md`

## 〇、范式落地通则【强制】

### 触发条件
应用任何工程范式(状态机 / 注册表 / DIP / 幂等键 / 检查点 / 失败模式 / 不变式 / 任何附录 A 的范式)。

### 必须输出(任务完成汇报段)
- `用了哪些范式`:每条给"范式名 + 应用在哪个文件/函数 + 一句话说明"
- `刻意不用哪些经典范式`:每条给"范式名 + 不用的原因"(对应诊断报告"我不会用什么"块)

### 推荐(不强制)
- 代码相关位置加注释 `# 范式: <名> — <一句话说明本处如何应用>`,便于事后定位

### 阻断条件
- 声明使用范式但汇报段未列 → **[阻断] 补汇报**
- 汇报段无"不用什么经典范式" → **[阻断] 显式列出**

## 一、思想范式

### 1. 依赖倒置(DIP)【强制】

> **2026-05-18 hook 接管声明**:跨层 import 违规已由 `import_lint.sh` hook + 项目根 `.importlinter` 配置物理拦截。
> 自检表只保留 hook 看不到的**语义层**:抽象 vs 具体、Protocol 边界。

#### 触发条件
新增类/模块,被 ≥ 2 处依赖,或需要 mock 测试,或包含 IO/外部依赖

#### 必须输出(只填 hook 查不到的语义项)
```
[DIP 自检]
- 这个东西是抽象(Protocol/ABC) vs 具体类:____
- 上层 import 的是抽象还是具体:____
```

#### 阻断条件
- 上层直接 `from X import 具体类`,且该类含 IO/外部依赖 → **[阻断] 改为依赖 Protocol/ABC**
- 跨层反向 import → **[hook 物理拦截]** 不在此重复

> 项目级层级定义见项目根 `.importlinter` 配置文件。

---

### 2. 状态机【强制】

#### 触发条件
满足任一即触发:
- 出现 ≥ 3 个布尔标志位
- `if status == 'X'` 类分支 ≥ 3 处
- 任务/对象有"未开始/进行中/已完成/失败/已撤销"类生命周期

#### 必须输出
```
[状态机自检]
- 状态枚举位置:____(文件 + 符号名)
- 合法转移表位置:____(文件 + 符号名)
- 状态切换方法:____(集中入口,如 _apply_state())
- 散落的 setattr/直接赋值检查:已 grep,□ 无 □ 有(位置 ____)
```

#### 阻断条件
- 状态分散在多个 if/else,无显式状态表 → **[阻断] 列出状态枚举 + 转移表**
- 存在不在转移表里的隐式状态切换 → **[阻断] 集中到状态表**

---

### 3. 注册表/策略【强制】

#### 触发条件
- 出现 `if x == 'a': ... elif x == 'b': ...` 分支 ≥ 3 个
- 且未来可能扩展新分支(用户加 / 插件 / 配置驱动)

#### 必须输出
```
[注册表自检]
- 当前分支数:____
- 扩展性预期:□ 不会扩展 □ 偶尔加 □ 频繁加
- 选用方案:□ 注册表 dict[key, handler] □ if/elif 链(说明为何不用注册表)
- 新增一个分支需要改几处:____
```

#### 阻断条件
- if/elif ≥ 3 分支 + 预期会扩展 + 仍用 if/elif → **[阻断] 改注册表或说明理由**

---

### 4. 异常分层捕获【强制】

> **2026-05-18 hook 接管声明**:
> 裸 except (E722) / blind except (BLE001) / try-except-pass (S110) / 不带 from (B904) / TRY 系列反模式 → 已由 `ruff_check.sh` 物理拦截。
> 本节只保留 hook 查不到的**语义层**:层级判断、宽捕原因、降级语义。

#### 触发条件
新增/修改 try-except;错误信息构造

#### 必须输出(只填 hook 查不到的语义项)
```
[异常分层自检]
- 本 try-except 所在层:□ 引擎层 □ 服务层 □ 边界层(CLI/HTTP/UI handler)
- 若用 except Exception 宽捕,原因:□ 边界层 □ 任务隔离 □ UI 顶层
- 若处理并恢复:
  - 恢复值的业务语义:____
  - 调用方如何区分正常 vs 降级:____
  - 日志级别:□ WARNING □ ERROR
```

#### 分层捕获规则(语义层,工具查不到)
- **引擎层**:只 raise,不 catch(除非真要降级,需明示业务理由)
- **服务层**:可 catch 转译成业务异常(`BusinessError`)
- **边界层**:必须 catch 兜底,转译为用户可见信息(不暴露 traceback)

#### 阻断条件(语义层)
- except Exception 未填宽捕原因 → **[阻断] 填三选一**
- 处理并恢复未填三项 → **[阻断] 补齐**
- 错误信息含敏感字段(密码/token/key) → **[阻断] 移除**
- 引擎层吞了异常未上报 → **[阻断] 改为 raise,catch 移到服务/边界层**
- 边界层未兜底导致 traceback 暴露给用户 → **[阻断] 边界层加 catch + 转译**

> 裸 except / 吞错 / 丢 traceback / TRY 反模式 → ruff 已物理拦,不在此重复

### 5. 不变式与确定性【已由 hook 接管,不再列为思考层强制】

> **2026-05-18 hook 接管声明**:
> - `enumerate(set/dict.keys)` 不稳定排序 → `ruff_check.sh` 自定义 grep 拦截
> - 标准库 `random.*` 用于业务输出无 `random.seed()` → `ruff_check.sh` 自定义 grep 拦截
> - `numpy.random.*` 老接口 → `ruff NPY002` 拦截
> - `os.listdir` / `glob.glob` 未 sorted → 语义层,**仅"业务依赖顺序"时需 AI 判断**,无固定形式
>
> 触发 hook 报告后,AI 在响应中按报告位置加 `sorted()` / `random.seed()`,或在 `# 范式: 确定性 — 业务接受不可复现` 注释里说明即可。
> 本节原 3 条阻断子项已全部由工具链覆盖,不再要求填自检表。

### 6. 并发安全(语义)【强制】

#### 触发条件
新增/修改并发代码(多线程、多进程、async、QThread)

> 池选择(IO/CPU)由 ruff/工具链建议级查;本规则只查语义不变式。

#### 必须输出
```
[并发语义自检]
- 共享状态:□ 无(通过) □ 有:____
  - 加锁策略:□ Lock/RLock □ Queue □ 不可变共享 □ 不加锁(说明理由)
- 任务可中止/可取消:□ 是 □ 否
- 失败任务有可见性(日志/异常上抛/状态上报):□ 是 □ 否
- 资源可回收(无泄漏):□ 是 □ 否
```

#### 阻断条件
- 有共享状态但不加锁且无理由 → **[阻断] 说明加锁策略或不加锁理由**
- 任务失败静默 → **[阻断] 加日志/异常上抛/状态上报**

---

### 7. 接口契约稳定性【强制】

#### 触发条件
- 新增/修改公开方法(被外部模块调用)
- 修改跨模块调用的函数签名
- 暴露给前端/外部的 API

#### 必须输出
```
[接口契约自检]
- 接口名称:____
- 暴露范围:□ 模块内 □ 跨模块 □ 公开 API
- 变更类型:□ 新增 □ 兼容修改 □ 破坏性变更
- 五项稳定性核对:
  □ 参数:增删/类型/默认值是否兼容
  □ 返回结构:字段是否稳定
  □ 异常类型:透传/转换语义是否一致
  □ 副作用:是否新增 IO/状态修改
  □ 性能:复杂度量级是否变化
- 调用方影响清单(破坏性变更必填):____(grep 列出)
- 兼容方案:□ 加新参数带默认值 □ 加新方法保留旧方法 □ 升版本号 □ 用户已确认接受破坏
```

#### 阻断条件
- 破坏性变更未列调用方影响清单 → **[阻断] 列全部调用方**
- 删除返回字段或改字段类型且未升版本 → **[阻断] 升版本或保留兼容字段**
- 公开方法返回 dict/Any 而非 dataclass/TypedDict/Pydantic → **[阻断] 用结构化类型**

## 附录 A:推荐级规则(完成后自查)

工具链能查的部分**优先交给 ruff/mypy/import-linter**;以下为思想层补充提醒,完成后自查。

### A.1 SRP 关注点分离
- 函数:不要在一个函数里混"编排 + 逻辑 + IO"三层
- 类:职责单一,超 300 行考虑拆

### A.2 复用与 DRY
- 同文件相同逻辑 ≥ 3 次:抽公共函数
- 跨文件相同逻辑 ≥ 2 次:提取到公共模块
- 优先级:复用现有 → 扩展现有 → 修改现有

### A.3 失败模式(简要,详见 `data.md` § 8)
- 多步写入:声明原子边界,部分成功处理
- 幂等键:重试安全

### A.4 可测试性
- 时间通过参数注入(不直接 `datetime.now()`)
- 随机源通过参数注入
- IO 通过参数/依赖注入

### A.5 纯函数与副作用
- 核心处理函数:接收数据 → 返回结果 → 不做 IO
- 副作用集中在边界层
- 报告进度通过 yield 或回调

### A.6 单一事实源(SSOT)
- 同一份状态只有一个权威源
- 跨组件/模块复制 state 时显式声明 source

### A.7 性能基线
- 新项目首次启动 / 老项目首次修改前,记录基线(启动时间、核心耗时、内存峰值)
- 优化前先定位热点,禁止猜测式优化

## 附录 B:工具链接管的规则(不在此重复)

|--------|----------|

| print 作正式输出 | ruff T201 |

| 硬编码临时路径 | ruff S108 |
| 默认参数可变 | ruff B006 |
| 函数内动态 import | ruff PLC0415 |
| 死代码 / 未用 import | ruff F401, vulture |
| 函数 > 50 行 | ruff PLR0915 |
| 类 > 300 行 | radon / ruff |
| 缺类型注解 | mypy --strict + ruff ANN |
| 公开方法返回 dict/Any | mypy + ruff ANN401 |
| 跨层 import / 循环依赖 | import-linter |
| try-except 反模式(TRY002/003/300/301/400/401) | ruff TRY |
