# 项目接手

## 文件定位
- **按需加载**:首次接触项目、新模块、或用户要求"接手"时读
- 接手的目标是**理解项目**(读文档、画调用链、识层级),不是改项目
- 接手完成后,根据后续是新增功能还是修改老代码,分别走 `flow_new_project.md` / `flow_legacy_project.md`
- 配套机制:`PROJECT_CONTEXT.md` 是接手产物,下次直接读跳过本流程

---

## 0. 触发条件
- 首次接触新项目目录或新模块
- 用户明确说"接手"、"理解一下"、"先熟悉熟悉"
- 切换到陌生工作目录,需要建立心智模型才能动手

**不触发**:
- 纯文档阅读、一次性脚本(无后续改动意图)
- 已有 `PROJECT_CONTEXT.md` 且未过期 → 直接读取,跳过本流程

---

## 1. 前置:开局体检

执行本流程前必须先完成 [workflow.md](workflow.md) § 6.1 开局体检(仓库根 / .gitignore / 暂存区 / 密钥 / 工具链)。

**基础设施异常未处理时不得开始接手流程。**

---

## 2. 核心步骤(6 步)

| 步骤 | 动作 | 产出 |
|------|------|------|
| 1 | **读文档** | README → CLAUDE.md → 项目总结。无文档则向用户索取背景/流程/问题 |
| 2 | **找入口** | 3-8 个,标注用途。GUI 找 handler / CLI 找 main / Service 找公开方法 |
| 3 | **画调用链** | 入口 → 第一层 → 第二层,确认函数签名 |
| 4 | **识层级** | UI 层 / 服务层 / 引擎层 / IO 层,标注每层职责 |
| 5 | **标状态机** | GUI 按钮状态流转、任务流程状态(若适用) |
| 6 | **生成文档** | 写入 `PROJECT_CONTEXT.md`,向用户确认理解无误 |

---

## 3. PROJECT_CONTEXT.md 模板

```
# 项目接手记录:____

## 项目本质
一句话描述这个项目在干什么。

## 入口清单
| 入口 | 类型 | 用途 |
|------|------|------|

## 调用链(主路径)
入口 ____ → ____ → ____

## 分层
- UI 层:____
- 服务层:____
- 引擎层:____
- IO 层:____

## 状态机(若适用)
____

## 已知遗留 / 红线
- ____(用户口述或文档提到的"别动这块")
```

---

## 4. 阻断条件

- 未完成接手清单直接改代码 → **[阻断] 易出现调用链断裂、幽灵引用、状态不一致、层级混乱**
- 基础设施异常未报告就开始接手 → **[阻断] 先跑 workflow.md § 6.1 开局体检**
- `PROJECT_CONTEXT.md` 与代码现状已不一致(如已删的入口仍在文档里) → **[阻断] 先更新文档,不能基于过期心智模型动手**

---

## 5. 与流程层文件的衔接

接手完成后:
- 用户要**新增功能/新模块**,且涉及架构决策 → 走 `flow_new_project.md`
- 用户要**改老代码/修 bug/重构** → 走 `flow_legacy_project.md`(其门 1/2/3 与本流程的"读文档/找入口"互补,不是替代)

---

## 6. 反模式

- ❌ 跳过文档直接看代码,导致漏掉用户口述的红线
- ❌ 入口找太多(>10 个)摊平了重心,实际抓不住主路径
- ❌ 调用链只画一层就交付,深度不够支撑后续决策
- ❌ 不写 `PROJECT_CONTEXT.md`,下次接手又重做一遍
- ❌ 接手中发现基础设施异常不汇报,蒙头继续
