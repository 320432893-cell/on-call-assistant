
# GUI规则（PySide6）强制版

## 文件定位
- 本文件只包含**强制阻断级**规则，推荐级规则移至注释附录
- 违反即阻断，无阻断条件的陈述句已删除

---

## 1. 状态机规则【强制】

### 触发条件
新增/修改多状态流转（按钮可用状态、任务生命周期状态、页面状态等）

### 必须输出
```
[状态机自检]
- 状态表名称：________________
- 状态表位置（行号）：__________
- 状态切换方法：_apply_state() / 其他：______
- 检查项：
  □ 无散落setEnabled/setVisible调用
  □ 所有状态迁移在状态表中定义
  □ 新增状态迁移条件已说明
```

### 阻断条件
上述检查项任一未勾选 → **[阻断] 状态机未显式化，请补全状态表和_apply_state方法**

### 触发条件
新增/修改按钮交互（尤其是触发耗时操作、危险操作）

### 必须输出
```
[按钮自检]
- 按钮类型：主要 / 次要 / 危险
- 危险按钮判定依据（若是）：________________
- 四态处理：
  □ 正常态
  □ 悬停态（hover）
  □ 按下态（pressed）
  □ 禁用态（disabled）
- 耗时操作防护：□ 点击后立即禁用/更新状态防重复点击
```

### 阻断条件
- 危险按钮无二次确认设计 → **[阻断] 危险操作必须二次确认，请补充确认对话框设计**
- 耗时操作无防重复点击 → **[阻断] 请补充点击后状态变更逻辑**

## 5. 错误提示规则【强制】

### 触发条件
新增/修改**面向用户的错误提示 UI**（弹窗、状态栏、内嵌错误信息）

> 异常捕获与处理逻辑(try-except / raise from / 错误信息构造)由 `code.md` § 4 异常分层捕获 阻断,本规则只管 UI 表现。

### 必须输出
```
[错误提示 UI 自检]
- 错误场景：________________
- 提示方式：□ 阻断弹窗 □ 非阻断弹窗 □ 内嵌 □ 状态栏
- 提示内容（必填两项以上）：
  □ 发生了什么（业务语言描述，非异常类名）
  □ 影响范围（数据是否丢失/操作是否部分完成）
  □ 建议处理（用户能做什么）
- traceback 屏蔽：□ 仅写日志 □ 展示给用户（阻断）
- 是否可恢复：□ 是，恢复路径：____ / □ 否
```

### 阻断条件
- traceback 直接展示给用户 → **[阻断] traceback 仅写日志，UI 提示用业务语言**
- 提示内容少于 2 项 → **[阻断] 至少包含"发生了什么 + 影响范围 / 建议处理"中的两项**

## 6. 耗时任务 UX 规则【强制】

### 触发条件
实现耗时操作（网络请求、文件处理、批量任务、预计 > 5 秒的操作）

### 必须输出
```
[耗时任务 UX 自检]
- 任务类型：________________
- 预计耗时：________ 秒

—— 执行中反馈（必须至少一种）——
□ 百分比进度
□ 阶段文字
□ 日志流

—— 状态完整性 ——
- 状态定义：□ 未开始 □ 执行中 □ 已暂停 □ 已停止 □ 已完成 □ 失败
- 停止 vs 失败区分：□ 是（用户主动停止 vs 系统异常） □ 否（阻断）

—— 中止机制（耗时 > 5 秒必填）——
□ 用户可见的中止按钮（"取消"/"停止"）
□ 中止信号路径：UI → Worker → 实际操作
□ 中止响应延迟：________ 秒
□ 中止后中间产物处理：清理 / 保留（说明：________）
□ UI 状态回退到"未开始"或"已中止"

—— 完成反馈 ——
□ 视觉变化 / 弹窗 / 自动跳转（任选）
```

### 阻断条件
- 执行中无任何反馈勾选 → **[阻断] 耗时操作必须有进度/阶段/日志至少一种反馈**
- 停止与失败未区分 → **[阻断] 用户主动停止和系统异常必须区分（日志+UI 都要分）**
- 耗时 > 5 秒无中止按钮/无中止路径 → **[阻断] 必须有用户可见的中止入口及信号路径**
- 中止后无中间产物处理策略 → **[阻断] 明确清理或保留策略**

## 7. 后台任务规则【强制】

### 触发条件
GUI 中后台执行耗时任务（可能阻塞主线程的操作）

> 并发模式选型（线程池 vs 进程池 vs async）、共享状态加锁、失败可见性 由 `code.md` § 6 并发安全 阻断；本规则只管 GUI 主线程不卡 + 结果回到主线程。

### 必须输出
```
[后台任务自检 - GUI 专项]
- 任务执行方式：□ QThread □ QRunnable + QThreadPool □ 其他（说明：________）
- 主线程阻塞防护：
  □ 已确认 IO/计算不在主线程
  □ 长循环已让出主线程（processEvents / 信号触发）
- 结果回传机制：
  □ Signal-Slot（推荐）
  □ QMetaObject.invokeMethod
  □ 回调 + invokeMethod 包装到主线程
  □ 直接在 worker 线程操作 UI（阻断）
- 高频刷新处理：□ 已加节流/缓冲（日志/进度更新 ≥ 50ms 一次）
```

### 阻断条件
- 任务执行方式非 QThread/QRunnable 且未说明 → **[阻断] GUI 后台任务必须用 QThread/QRunnable**
- 在 worker 线程直接操作 QWidget → **[阻断] UI 操作必须回到主线程（Signal-Slot 或 invokeMethod）**
- 无任何结果回传机制 → **[阻断] 必须定义结果回传方式**
