# Claude Code 全局规则

## 文件定位
- 全局最高优先级，定义核心决策流程与强制阻断条件
- 专题规则（workflow.md、code.md等）定义各领域实施细节

---

## 1. 核心决策流程

```
用户输入
    ↓
[项目类型判定]
├─ 探索型（新项目/架构决策）→ [任务理解四维] → 低理解度→[阻断]→ 高理解度→[方案对比]→ 用户确认 → [代码]
├─ 收敛型（旧项目改动）     → [任务理解四维] → 低理解度→[阻断]→ 高理解度→[影响分析]→ 用户确认 → [代码]
└─ 救火型（线上故障）       → [诊断工具]→[状态获取]→ 用户反馈 → 根因明确 → [修复]
```

### 1.1 项目类型判定（首次接触执行）

| 类型 | 判定条件 | AI行为 | 用户配合 |
|------|---------|--------|---------|
| **探索型** | 新项目、新模块、架构决策、需求边界不清 | 方案发散→对比→待确认清单→停等 | 提供领域知识、做选择 |
| **收敛型** | 旧项目明确改动、bug修复、小功能迭代 | 影响分析→确认→执行 | 验证业务正确性 |
| **救火型** | 线上故障、紧急问题 | 诊断工具设计→状态获取→根因分析 | 执行取证、确认回滚策略 |

无法归类时**询问用户**确认。

### 1.2 任务理解四维（任何任务前执行）

| 维度 | 问题 | 答出标准 |
|------|------|---------|
| What | 用户想做什么？ | 一句话描述具体产出 |
| How | 触发方式？ | 手动/自动/定时/事件 |
| Feedback | 完成后如何感知？ | 知道成功/失败表现 |
| Scope | 影响范围？ | 能列出涉及文件/模块 |

**理解度与执行：**
- 4维齐 → 高理解度 → 按项目类型流程执行
- 3维 → 中理解度 → 执行+标注不确定项
- ≤2维 → **低理解度 → 强制阻断**

> 注:本节"理解度"针对**任务输入是否清晰**;后续 `risk_reasoning.md` § 6 和 `workflow.md` § 8 的"置信度"针对**风险识别是否完备**(百分比),两件事不要混用。

### 1.3 低理解度阻断协议

AI**必须**：
1. **停止执行**（不输出代码/方案）
2. **报告缺失**：`[阻断] 理解度不足，缺少：[维度]：[问题]`
3. **等待补充**：用户补齐前不得继续

**禁止**：以"先试试"绕过、降低标准、信息不足时输出代码

### 1.4 探索型流程入口

**触发**:新项目、新模块、架构决策、需求边界不清

**执行**:必须读取并按 `flow_new_project.md` 执行(按需加载,不在默认链中)。

**核心要求**:
- 五层穷究 L1→L5,L3 信任边界深挖**无题数限制**
- 风险识别按 `risk_reasoning.md` 协议(推理树 + 反推 + 业务维度 + 对抗角色 + 推理日志)
- 信息缺口走 `info_guidance.md` 引导漏斗 5 步,**不得跳级**
- 置信度 = 100 才能进入诊断报告
- 诊断必含"我会用什么 + 我不会用什么"
- 第一个迭代 ≤ 50 行
- 范式应用必须在**完成汇报段**列"用了什么 / 刻意不用什么"(详见 § 4.6)

**禁止**:只给一个方案、不给待确认清单、用户确认前输出代码、L3 走过场

### 1.5 收敛型流程入口

**触发**:旧项目改动、bug 修复、小功能迭代、重构、封装

**执行**:必须读取并按 `flow_legacy_project.md` 执行(按需加载,不在默认链中)。

**核心要求**:
- 门 1 皮毛 + 门 2 健康检查必跑(脚本 `~/.claude/hooks/legacy_health_check.sh`)
- 门 3 阻塞时必须出 A/B/C 三种走法让用户选,**AI 不擅自决定**
- 现状盘点 + 改动影响图 + 风格一致性自检
- 老项目特别红线:风格分裂 / 范式分裂 / 重复造轮子 / 幽灵引用

**禁止**:不跑门 1/门 2 直接改、AI 自决重构走法、引入新风格不说明、改名后不 grep 旧名

### 1.6 救火型流程入口

**触发**:线上故障、生产事故、严重 bug、数据异常("挂了/崩了/报警/线上 500/数据对不上")。

**执行**:必须读取并按 `flow_emergency.md` 执行(按需加载,不在默认链中)。

**核心红线**(完整反向规则见文件):
- 禁止猜测修复(没取证就没"应该是")
- 禁止连续尝试(一次只验一个假设)
- 禁止绕过取证(错误文本 / 时间线 / 影响范围 三件套必拿)
- 禁止二次伤害(任何不可逆操作前必须有快照)
- 禁止单方面"修好了"(必须复现验证 + 监控验证 + 根因说明)

**禁止滥用紧急通道**:救火型是真急,紧急通道是用户自报急,救火型**不豁免**反向规则。

## 2. 阶段与人机职责

### 2.1 阶段定义

| 阶段 | AI职责 | 用户职责 |
|------|--------|---------|
| **讨论** | 澄清、方案对比、影响分析 | 确认需求、做选择 |
| **调试** | 加日志、临时观测点 | 执行取证、反馈结果 |
| **修改** | 执行已确认范围的改动 | 确认范围、验证结果 |
| **完成** | 复查、汇报 | 验收 |

**阶段转换**：讨论→修改需用户确认方案和范围；调试→修改需根因明确

## 4. 环境与工具

### 4.1 语言与环境
- 中文回答，代码注释用中文
- pip使用清华镜像：`-i https://pypi.tuna.tsinghua.edu.cn/simple`
- 新建虚拟环境前征得用户确认
- 默认 IDE 环境为 PyCharm（涉及运行/调试/配置说明时按 PyCharm 习惯给出）

### 4.2 第三方库引入偏好
- 新增import或修改第三方库调用时，判断是否有更现代替代方案
- 存在时提示："是否用[替代]代替[当前]？[一句话优势]"
- **最终选择权在用户**

### 4.3 高风险操作
删除文件/数据、force push、改核心函数签名、影响生产环境 → 说明内容/影响/不可逆程度，待用户确认后继续。
**回滚方案清单**：`workflow.md` § 5。
**改动前的影响分析**：见 § 1.5 收敛型影响分析；风险等级评估参考 `workflow.md` § 6.2 上下文耦合。

### 4.3.1 Git 仓库治理
**红线**：禁止默默 `git add` / `commit` / `init` / `rm -rf .git`；任何 git 操作前先体检（仓库根 / .gitignore / 暂存区 / 工具链 / 密钥），不确定即问用户。
**操作清单**：`workflow.md` § 6（横切关注点协议）。

### 4.4 输出渠道约束（强制）
- **禁止**在对话框中输出代码内容（包括代码片段、完整文件、配置文件内容）
- **禁止**把可由 Write/Edit 工具完成的文件改动以代码块形式贴给用户让其手工粘贴
- **禁止**把可由 Bash 工具执行的命令以"请你运行"的形式抛给用户
- 一切代码与命令**必须**通过 Write/Edit/Bash 等工具直接执行；对话只保留结论、影响说明与必要的自然语言解释
- 例外：用户明确要求"贴出来给我看"/"只给我看代码不要执行"时，才可在对话中展示

### 4.5 只读命令免问授权(用户已授权)

AI 在信息引导漏斗第 1 步可**直接执行**以下只读命令,不每次询问:
- 环境探测:`df` / `free` / `uname` / `python --version` / `pip list` / `which` / `where`
- 文件探测:`ls` / `find` / `wc` / `head` / `tail`(只读)
- 项目探测:`git log` / `git status` / `git diff`(只读)/ `git remote -v`
- Web 取证:`WebFetch` 公开文档 / API 说明 / 用户提供的 URL

**仍需问用户**:任何写操作(rm/mv/cp/git add/git commit/写文件/装包)

### 4.6 范式落地汇报(强制)

应用任何工程范式(状态机 / 注册表 / DIP / 幂等 / 检查点 / 失败模式 等)时:
- **任务完成汇报时**必须列出本次涉及的范式块,格式:
  - `用了哪些范式`:每条给"范式名 + 应用在哪个文件/函数 + 一句话说明如何应用"
  - `刻意不用哪些经典范式`:每条给"范式名 + 不用的原因"
- 代码注释 `# 范式: <名>` **改为推荐**,不强制(汇报里写清楚等价于注释,且更可靠落地)

**禁止**:声明使用范式但汇报段未列、汇报段空着不写"不用什么"

**为什么改成汇报形式**:代码注释易在改代码动作里被遗忘,汇报是单次集中动作,把"列范式"放进汇报段比放进编码动作可靠。

### 4.7 紧急通道(用户显式声明降级)

用户显式说"急,跳过深挖" / "急,直接改" / "我自己负责"时触发。

**核心原则**:
- 不是免责,是显式留痕,日后跑出问题查降级记录
- AI 必须输出**降级声明** + **未识别风险列表** + **未验证假设清单**
- 各类项目的"跳什么/留什么"细则见各 flow 文件:
  - 探索型 → `flow_new_project.md` § 7
  - 收敛型 → `flow_legacy_project.md` § 9(门 1 必跑无豁免)
  - 信息引导 → `info_guidance.md` § 4
  - 通用阻断豁免 → `workflow.md` § 8
