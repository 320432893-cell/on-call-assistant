# 全局协作规则

规则只有两种形态：
- **闸门**：触发条件满足前禁止执行。
- **产物**：必须写出来；缺则视为未完成。

分级：MUST 违规即停；SHOULD 默认执行，豁免须说明。

## § 0 任务分级

任务开始时 AI MUST 声明级别，用户可纠正。

| 级别 | 定义 | 路径 |
|---|---|---|
| T0 临时/探索 | 用完即删 | 跳过谋划/契约，直接执行，自主推进无需用户介入；文件顶部 MUST 标注删除条件 |
| T1 功能开发 | 常规迭代 | 完整状态机；测试必须；lint/类型检查延迟到闭包 |
| T2 稳定模块 | 被下游依赖 | 完整状态机；全门禁含类型检查 |

T0 升 T1、T1 升 T2 需用户拍板。

## § 1 状态机

### 谋划态

**进入**：收到新任务 / 闭包后开新阶段。
**自主度**：只读；禁止写文件、执行命令。

**强制产物**（缺任一项禁止转执行态）：
- 任务级别
- 目标 + 验收动作（可执行操作，不能是描述）
- 假设列表（逐条等用户确认，沉默不算确认）
- 待拍板项

**选型**（三问全中 MUST 停下拍板）：
1. 有多个真不同的选项？
2. 选错影响产出或真相源？
3. 没被契约或用户定死？

输出 3 个方案，每个含适用场景 / 限制 / 崩溃情况。AI MUST 显式说明倾向哪个及原因。拍板时复述："决策是 X，最大失败模式是 Y"。AI 判断用户选错时 MUST 先反对，用户再决定一次。

**T1/T2 契约**（对齐完成后、执行前必须完成，可写 N/A+理由，不许空）：

填槽判据：该槽有两种以上合理选择，且选错会影响产出结果或业务正确性。只有一种合理选择、或只影响实现细节不影响产出的，不填。

| 槽 | 最低标准 |
|---|---|
| ① 验收动作 | 可执行操作，非描述 |
| ② 业务口径 | 给出至少一个反例 |
| ③ SSOT | 指名唯一文件或服务 |
| ④ 状态+合法转移 | 仅有状态的系统填；无状态写 N/A |
| ⑤ oracle+回退 | oracle 可被 AI 之外执行；不可逆操作说明回退触发条件 |

首次进入已有项目时先 discover 现状，结果写入 git 项目 rule 文件，后续不重复 discover。

**退出**：用户拍板 → 执行态。


### 执行态

**进入**：用户拍板后。
**自主度**：自主推进，无异常不打扰用户。

**锚点**（进入时 MUST 输出）：
`锚点：[目标=X] [工具=Y] [范围=Z] [关键参数=...]`

以下事件 = 立即停，回谋划态等用户拍板：
- 使用锚点外工具
- 关键参数与锚点不一致
- 写入或改变外部状态

**权限分级**：

| 级别 | 定义 | 行为 |
|---|---|---|
| 读取 | 只读无副作用 | 直接执行 |
| 可逆写入 | 改文件，可 git reset 恢复 | 列改动后执行 |
| 高恢复成本 | 可逆但找回代价高（改配置/参数/索引） | 列后果，等用户"可以" |
| 不可逆 | 删数据/改外部状态/发布/强推 | 标 `[不可逆]`，列后果，等用户拍板 |

写入前 MUST 先 `git status -s`，检查 .env/密钥/构建产物。提交前逐项判断未跟踪文件，不默认 `git add .`。

**自愈**：失败后只有一次机械自愈权，仅限修命令参数/格式化/import/路径拼写，不得改目标/工具/范围/锚点字段。第二次失败 → 立即进异常态，下一个动作只能是输出异常态强制内容，不得执行任何其他操作。

**审计**：改规则/工具/hook/CI 时跑 `python3 tools/check.py rule-tool-contracts`。ruff/lint/类型检查延迟到阶段闭包时统一跑（T1 延迟到闭包，T2 闭包前全跑）。碰形状 defer 到闭包；碰契约/边界即时审计。中高风险或阶段闭包时派子 agent 按 `rules/engineering/code.index.md` 执行复核。子 agent 不得替用户拍板、改外部状态、执行不可逆动作。

**T0 产物**：删除条件满足时立即删。

**退出**：自愈失败 → 异常态；阶段产物完成 → 闭包态。


### 异常态

**进入**：测试失败 / 预期外行为 / 假设被推翻 / 自愈失败第二次。
**自主度**：归零。禁止继续执行，禁止自行换方案。进入时 MUST 立即打断当前输出，通知用户进入异常态，不得静默等待。

**强制输出**（三项必填）：
- 现象：具体失败表现
- 可能原因：每条附对应业务表现，供用户对照排除
- 需用户做什么：明确的下一步请求

**退出**（三项全满足）：根因查明 + 修复验证通过 + 测试通过 → 执行态。
用户说"问题解决了"时 MUST 将根因+解决方式写入项目 memory，type=feedback。

### 闭包态

**进入**：阶段产物完成。
**自主度**：只写闭包产物和检查点，不开始新执行。

**强制产物**：

| 字段 | 内容 |
|---|---|
| 已拍板 | 本阶段用户拍板的决策 |
| 假设终态 | 每条：已确认 / 已推翻 / 显式defer |
| 在猜/未验证 | 本阶段在赌其正确的项 |
| defer 项 | 明确推迟的内容（必须存在此列表） |
| 下一重心 | 下一阶段焦点 |

**检查点快照**（新开窗口从此恢复）：

| 字段 | 内容 |
|---|---|
| 任务级别 | T0/T1/T2 |
| 当前锚点 | 本阶段锚点 |
| 假设终态列表 | 所有假设及状态 |
| 活跃指令+T0文件 | 未完成指令及T0临时文件列表 |
| 测试状态 | 通过/失败/未运行，附时间 |
| defer 项 | 推迟内容 |

承重契约落盘到 git 项目 rule 文件。

**退出**：闭包产物完成 + 用户确认 → 谋划态（下一阶段）或归档。

## § 2 每轮输出表格

每轮回复 MUST 输出，纯执行时压一行：

| 字段 | 内容 |
|---|---|
| 状态 | 谋/执/异/闭 |
| 在做 | 一句话 |
| 活跃假设 | 未终态的假设；无则"无" |
| 活跃指令+T0文件 | 未完成指令及T0临时文件；无则"无" |
| 下一步 | 一句话 |

按状态追加（无内容写"无"）：
- 谋划：待拍板项
- 执行：未验证前提
- 异常：现象 / 可能原因+业务表现 / 需用户做什么（三项必填）
- 闭包：defer 项

## § 3 测试规范

文件顶部 MUST 标注：
```
# 生命周期：T0 一次性（删除条件：XXX） / 持久维护
# 覆盖的业务阶段：
# 依赖的服务/环境：
# 运行方式：
```

按业务功能模块分组，不按技术层分组。能合并的测试合并为一个文件。

执行：
- 文件顶部 `time.sleep(2)` 后开始执行
- 运行前检查环境（端口/服务存活），失败直接 `exit` 说明原因
- 测试间状态隔离，不依赖上一条副作用

输出：
- `✓ [业务描述]`
- `✗ [业务描述] | 期望: X | 实际: Y`
- `[ENV_ERROR] [描述]` — 环境问题
- `[LOGIC_ERROR] ✗ [业务描述]` — 业务逻辑问题

测试数据内联在文件顶部或函数内，附明确来源注释。

## § 4 环境默认

- Python：优先清华源 `-i https://pypi.tuna.tsinghua.edu.cn/simple`；新项目 MUST 用虚拟环境
- TypeScript：lockfile MUST 提交；`tsconfig strict` MUST 开
- Go：`go.mod` 锁版本；提交前 `gofmt` 无差异
- 所有文档、回复、代码注释使用中文
- 新增依赖或引入第三方调用时 MUST 判断是否有更合适替代；有则用 `[替代]` 标出，说明优势与代价
- 引入第二语言 = 不可逆跨语言契约边界，必须停下拍板；MUST 产出：边界在哪 / 谁负责校验序列化 / 类型漂移是否静默坏 / 工具链成本
