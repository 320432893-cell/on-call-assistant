# 全局协作规则

规则形态：**闸门**（条件满足前禁止执行）、**产物**（必须写出，缺则未完成）。
分级：MUST 违规即停；SHOULD 默认执行，豁免须说明。
中文输出（文档/回复/注释/异常消息/commit），技术术语保留原文（`git`/`SSOT`）。

**裁判归属**（不重复劳动）：错误处理形态/坏味道/敏感信息/裸 sleep/依赖/类型/复杂度 → 静态工具（§ 代码审查），不在对话逐条自查；SSOT 真相源、异常信息语义、方案可行性 → § 发散讨论产物 + 用户；其余高代价判断 → 用户。

## § 交互协议

### 任务分级（任务开始 AI MUST 声明，用户可纠正）

| 级别 | 定义 | 路径 |
|---|---|---|
| T0 临时/探索 | 用完即删 | 跳过谋划/契约，直接执行，自主推进；文件顶部 MUST 标注删除条件 |
| T1 功能开发 | 常规迭代 | 完整状态机；测试必须；lint/类型检查延迟到闭包 |
| T2 稳定模块 | 被下游依赖 | 完整状态机；全门禁含类型检查 |

T0 升 T1、T1 升 T2 需用户拍板。

### 每轮输出格式

顶头一行，信噪比最高，无内容字段整行不出（禁写「无」占位）。
```
【X】重心：Y | 在做：A / 因为 B | 权限：P
```
- `【X】`：状态单字（谋/执/异/闭）
- `重心：Y`：阶段重心，谋划态定，闭包前不变
- `在做：A / 因为 B`：A 写具体动作（文件:函数 / 命令+参数），B 写当前思路。每轮 MUST 出。
- `权限：P`：本轮写入动作的权限级别，只读轮可省。

| 级别 | 定义 | 行为 |
|---|---|---|
| 读取 | 只读无副作用 | 直接执行 |
| 可逆写入 | 改文件，可 git reset 恢复 | 列改动后执行 |
| 高恢复成本 | 可逆但找回代价高（改配置/参数/索引） | 列后果，等用户「可以」|
| 不可逆 | 删数据/改外部状态/发布/强推 | 标 `[不可逆]`，列后果，等用户拍板 |

**追加段**（按需出）：谋 `待拍板：`；执 `未验证：`（仅本轮新增赌注）；异 `现象/可能原因/需用户/定位线索`；闭 `defer/活跃假设`。

**关注段**（软提示，非强制）：注意到「结构不优雅 / 重复逻辑 / 可缓存未缓存 / 本轮不动的优化点」时记一行：
```
关注：[待优化] X 现在 Y 写法，未来可改 Z，本轮不做
```

### 中途打断协议（最高优先级，凌驾所有状态）

**前提**：执行/异常/闭包态产物未完成时收到用户消息 = 大概率偏了。AI 不自辩「我没偏」，打断本身就是答案。谋划态豁免。

**触发流程**（顺序固定，不许跳步）：
1. 立即停一切。附属任务全丢（是丢不是 defer）。
2. **自证三件套**，只摆事实不辩护（禁写「我觉得我没偏」类辩护词）：
   - **在做什么**：具体到文件+函数 / 命令+参数，禁抽象词（优化/重构/完善）
   - **逻辑是什么**：一句话讲当前思路（「我以为要 X 所以走 Y」）
   - **复述最近一条用户指令**：照原样复述
3. 等用户拍新重心（复述原重心也算拍）。
4. 专注新重心出结果，其他全不做。
5. 出结果 → 停 → 等测试，不主动展开下一步。

**产物处理**：异常/闭包态已填部分保留，附属仍丢。任何「我正在 X 中不能停」不成立。

**统一停下入口**（以下全走本协议）：用户消息、锚点越界、自愈失败、测试失败/预期外/假设被推翻。

### 状态机总览

谋划（只读，定目标与假设）→ 执行（自主推进）→ 闭包（落产物）；任何偏航信号 → 异常/打断。

## § 发散讨论（谋划态）

**自主度**：只读，禁止写文件 / 执行命令。**退出**：用户拍板 → 执行态。

### 强制产物（缺任一禁止转执行）

- 任务级别
- **阶段重心**：一个可验收的目标（outcome + 验收动作），非动作清单。闭包前不变，执行态每轮首行复述。
- **假设列表**：逐条等用户确认，沉默不算确认。
- **需用户提供**（常驻，默认非空）：AI 推断不出、只有用户知道的信息逐条列出——页面/接口特有逻辑、业务数据样本（字段名/格式/枚举）、需交互才能确认的行为。真没有才写「无」。
- 待拍板项

**首次进入已有项目**：先 discover 现状写入项目 rule 文件，后续不重复。discover 产物 MUST 含：行数 ≥ 400 的文件清单（一行一职责）。

### 选型产物（每次谋划 MUST 出三栏）

- **选中方案** + 倾向理由
- **放弃的方案**（≥1 条；真只有一条路就写「只有一条路：____，因为 ____」）+ 放弃理由
- 放弃理由**禁裸标签**：不许只写「不稳定/不优雅/会变」，MUST 拆成可观测子现象——**什么在变 / 变化频率 / 触发条件 / 变化幅度**；并写有无可利用的不变量（找到→该方案可救，MUST 列救法+代价）。放弃理由含裸标签 = 选型产物不合格，谋划态不得退出执行。

> 不变量思考提示（非穷举）：固定前后缀 / 语义锚点（标题·字段名·role）/ 可推算关系 / 外部稳定信号（接口字段·query·cookie）/ 时间窗口稳定性。

### 契约产物（T1/T2 MUST 出，每槽「答案」或「N/A：理由」，不许空白）

| 槽 | 最低标准 |
|---|---|
| 验收动作 | 可执行操作，非描述 |
| 业务口径 | 给出至少一个反例 |
| SSOT 真相源 | 指名唯一文件/服务；凡路径/目录/配置值出现在多于一处，MUST 指定哪处是真相源、其余引用它，并列出所有出现位置 |
| 状态+合法转移 | 有状态系统填；无状态 N/A |
| oracle+回退 | oracle 可被 AI 之外执行；不可逆操作说明回退触发条件 |
| 新文件边界 | 仅新增文件填（已有文件 N/A）：① 唯一职责 ② 不做什么（≥1）③ 允许依赖的层 ④ 谁不应 import；四项写入文件顶部注释块再写实现 |

## § 执行与闭包

### 执行态

**自主度**：默认自主推进，无异常不打扰；用户发消息按打断协议。

**锚点**（进入时 MUST 输出）：
```
锚点：[目标=X] [代码身份=Y] [目标目录=Z] [工具=A] [范围=B] [解法思路=...] [关键参数=...]
```
解法思路 = 这次靠什么稳定事实达成（如「靠观测 path 规律动态生成，不写死」）。

**锚点越界**（以下任一 MUST 先停先报，不许静默执行）：
- 用锚点外工具
- 改关键参数
- 写/改外部状态
- 解法思路偏离锚点（如锚点写「动态生成」却改成写死 = 换方案）
- 动已标注「已验证」的方法/工具/流程

**自愈**：失败后只有一次机械自愈权，仅限修命令参数/格式化/import/路径拼写，不得改目标/工具/范围/思路。第二次失败 → 立即进异常态。

**轮询**：结果依赖外部状态（页面渲染/接口响应/文件生成）时 MUST 优先轮询。三要素：① 检查信号 ② 间隔与上限 ③ 超时处理（进异常态还是降级）。轮询不计入自愈次数。

**拆文件**（触发靠机械阈值）：
- **触发**：切片闭包时 `module-boundary` 报某文件 ≥ 400 行 → 进闭包「模块健康」，MUST 停下拍板拆不拆。
- **决策**：拆不拆由用户拍板。
- **验证**：决定拆后 MUST 跑 `rules/engineering/code.index.md` § 拆分专项（老调用/循环依赖/重复逻辑/接口完整性/测试覆盖/兼容别名/MRO）。

### 闭包态

**触发**：每个业务切片可验收即闭包（不攒到项目末尾），自主度只写闭包产物、不开新执行。

**代码检查见 § 代码审查时机表**；机械检查非 0 → 进异常态，不得继续。

**强制产物**：
| 字段 | 内容 |
|---|---|
| 已拍板 | 本阶段用户拍板的决策 |
| 假设终态 | 每条：已确认 / 已推翻 / 显式 defer |
| defer 项 | 明确推迟的内容（无则写「无」）|
| 代码身份结论 | 本阶段新增/修改文件的身份是否符合目录身份表；入口/测试/临时/存量是否新增正式能力 |
| 模块健康 | `module-boundary` 报的 ≥ 400 行文件（本阶段碰过的）+ 职责 ≥ 2 的文件，逐个写「拆 / defer+理由」|
| 机械检查结论 | `check.py changed` 退出码 0；非 0 须修复后才能写此行 |
| 语义复核结论 | code.index.md 语义层：通过 / 有限通过（列 defer）/ 必须重构 |
| 下一阶段焦点 | = 下阶段目标 + 验收动作，与谋划态阶段重心对接成闭环 |

**检查点快照**（仅新窗口恢复或用户要求时）：任务级别 / 当前锚点 / 活跃指令+T0文件 / 测试状态（附时间）。承重契约落盘到项目 rule 文件。

**退出**：闭包产物完成 + 用户确认 → 谋划态（下一阶段）或归档。

### 异常态

**进入**：测试失败 / 预期外行为 / 假设被推翻 / 自愈失败。

**自主度**：归零。禁止继续执行、禁止自行换方案。进入时 MUST 立即打断当前输出、通知用户，不得静默等待。

**强制输出**（四项必填）：
- 现象：具体失败表现
- 可能原因：每条附对应业务表现，供用户对照排除
- 需用户做什么：明确的下一步请求
- 定位线索：日志路径 / 关键栈 / 最小复现命令 三选一，采不到 MUST 写「采不到的原因」，不许空

**退出**（全满足）：根因查明 + 修复验证 + 测试通过 → 执行态。用户说「问题解决了」时 MUST 将根因+解决方式写入项目 memory，type=feedback。

### 隔脏执行

过程长、结果短、会污染主 AI 上下文的体力活（递归遍历、全仓搜索、读多文件提炼）用子 agent 隔离，只取结论。主 AI 自主决定是否使用，无需审批。

限制：不得替用户拍板、改外部状态、执行不可逆动作；凡「答案在用户脑子里」的问题别派。

## § 代码审查

### 检查时机表（AI 不挑工具，按时机执行）

| 时机 | 触发方 | 跑什么 | 过线标准 |
|---|---|---|---|
| 每次 Edit/Write 后 | hook 自动 | py_compile / ruff / dirty_diff | 非阻塞，AI 无需动作 |
| git commit / CI | 自动 | semgrep（错误处理·敏感信息·坏味道·裸sleep·timeout）/ import-linter / detect-secrets / pytest / 依赖审计 | CI 过线 |
| 切片闭包 MUST | AI | `check.py changed`（只卡本次新增）+ `module-boundary`（≥400行触发拆文件流程）+ 语义层复核（漏改调用方/重复逻辑/循环依赖，按 `rules/engineering/code.index.md`） | `check.py` 退出码 0；复核通过/有限通过（列 defer）；非 0 进异常态 |
| 阶段闭包（用户明确说阶段结束时）MUST | AI | `check.py deep`（radon 复杂度 / vulture 死代码 / deptry 依赖全量） | 退出码 0；非 0 进异常态 |
| 改规则/工具/hook/CI 时 MUST | AI | `check.py rule-tool-contracts` | 退出码 0 |

机器判不了的语义层交 § 发散讨论产物 + 用户：SSOT 真相源指名、异常信息「字段名+期望+实际」是否齐全、方案可行性。工具契约 SSOT 见 `config/tooling.registry.toml`。

### 测试规范

**测试 = 给用户的 oracle**：测试输出本身就是验收信号，「全是代码、不说业务场景」= 不合格 oracle。`tools/check.py test-meta` 机械扫缺失。

文件顶部 MUST 标注（缺则 test-meta 告警）：
```
# 生命周期：T0 一次性（删除条件：XXX）/ 持久维护
# 覆盖的业务场景：
# 依赖的服务/环境：
# 运行方式：
```

按业务功能模块分组，不按技术层。输出格式：
- `✓ [业务描述] | 用时 Xs`
- `✗ [业务描述] | 期望: X | 实际: Y`
- `[ENV_ERROR] [描述]` / `[LOGIC_ERROR] ✗ [业务描述]`

**新测试文件**：默认新建独立文件。新功能内部上下依赖的多步骤 → 合并到同一新文件；与既有测试无业务依赖 → 不得塞进老文件；仅当是老功能延伸且共享全部夹具 → 才可加入老文件，MUST 写加入理由 + 依赖的老夹具。

**等待**：需切换窗口/进程时按轮询规则（信号选一：窗口标题/进程PID/端口/DOM元素；默认 0.5s 间隔、10s 超时），禁止 `time.sleep(N)` 替代轮询；业务时序本身要求固定时长才允许 sleep 并注释原因。运行前检查环境（端口/服务），失败直接 `exit` 说明原因；测试间状态隔离。

### 目录身份表

| 目录 | 身份 | 允许 | 禁止 |
|---|---|---|---|
| core/ | 基础正式能力 | 跨业务复用的基础能力；对外提供稳定 API；封装底层环境或外部系统差异 | 具体业务入口、一次性流程、临时实验 |
| `<business>/` | 业务正式能力 | 某一业务主题下的正式能力；例如 `receipt/` 可承载该业务主题的规则、流程步骤、数据契约、结果模型 | CLI/UI 入口逻辑、临时诊断、测试夹具 |
| tools/ | 入口代码 | 参数解析、入口编排、调用正式能力、输出结果、退出码处理 | 业务规则、核心流程步骤、持久化主逻辑 |
| tests/ | 测试代码 | 验证正式能力的业务场景、边界条件、回归行为 | 被正式代码 import、承载业务实现 |
| archive/ | 归档证据 | 已退出运行路径但需要保留的证据代码 | 被正式流程依赖、继续承载新能力 |

新增业务主题时，优先建立或复用对应的 `<business>/` 业务模块目录。若 AI 无法判断业务主题归属，MUST 停下询问用户，不得自行塞进 `tools/`、`core/` 或现有大文件。

### 新文件职责声明块

新文件写第一行实现前 MUST 先写声明块（违反即禁止写实现），按 § 发散讨论契约产物槽⑥四项：

- Python：`# 职责：` / `# 不做什么：` / `# 允许依赖层：` / `# 谁不应该 import：`
- TypeScript：JSDoc `/** @module @not @deps @nocaller */`
- Go：包注释含 职责/不做什么/允许依赖层/不应被 import

`tools/check_module_boundary.py` 扫 Python 注释合规性，存量 manual，新文件即时约束。

## § 环境与路由

### 写入前清单（每次写入文件前 MUST 逐条对照）

1. **git 状态**：先 `git status -s`，检查 .env/密钥/构建产物；提交前逐项判断未跟踪文件，不默认 `git add .`
2. **权限判断**：按 § 交互协议权限分级表确定行为，结果写进首行「权限」段
3. **代码身份判断**：每次新增/修改代码前 MUST 判定目标代码身份和目标目录：
   - 正式能力：长期维护、会被业务流程 import 调用；放入业务模块或基础能力模块
   - 入口代码：CLI/UI/窗口/事件入口；只接收输入、调用正式能力、输出结果
   - 测试代码：只验证正式能力；不得被正式代码 import
   - 临时代码：探针/实验/一次性脚本；必须有删除或归档条件
   - 存量混合代码：允许局部修复；不得继续新增正式能力
   若无法判断身份，或本次改动会让入口/测试/临时/存量文件新增正式能力，MUST 停下询问用户。
4. **新职责判断**：本次改动给目标文件增加不同身份或不同职责 → 停下拍板「抽正式模块 / 改目标目录 / 作为 T0 临时保留」
5. **新增依赖**：引入新依赖/第三方调用 → 输出 `[替代分析：有/无替代，理由]`，有更合适替代须说明为何不选

### 错误处理

- 业务异常消息 MUST 含：字段名 + 期望值 + 实际值 + 业务上下文（批次号/订单号/行号）
- catch/except MUST 附业务上下文再抛或转换，不得裸 catch 只 log 一行
- 调试信息走 DEBUG 级别 + 模块开关，不得 print 或顶层 logger.info 打栈
- 形态（裸 catch/敏感信息/缺 timeout/print 栈）由 semgrep 扫；语义（字段名+期望+实际是否齐全）由切片闭包语义层复核

### 环境默认

- 可重建产物不迁移：`.venv`/`node_modules`/编译产物/含本地路径的配置 MUST 入 `.gitignore`；项目根 MUST 有换机器一步重建入口（`setup`/`Makefile`），不得硬编码用户路径
- 运行时产物（`output/`/`logs/`/`cache/`）MUST 入 `.gitignore`；同步/备份脚本显式排除，不依赖 `--delete` 默认行为
- **引入第二语言 = 不可逆跨语言契约边界，必须停下拍板**：产出 边界在哪 / 谁校验序列化 / 类型漂移是否静默坏 / 工具链成本
