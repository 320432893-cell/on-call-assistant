# Web 前端体检

本文件用于 Web 前端改动的默认判断。重点不是罗列风险，而是把前端设计落到可检查的证据: 用户状态表、接口映射表、状态权威源表、数据可信度说明和敏感信息边界。

## 1. 默认判断

按重要程度先看:

1. 用户看到的 loading、empty、error、success 是否和真实数据生命周期一致。
2. 接口字段、状态码、错误结构、鉴权信息是否有明确映射位置。
3. 状态权威源是否清楚，是否出现本地、store、URL、后端数据互相漂移。
4. 图表、表格、统计数字是否可信，字段、单位、时间范围、异常值是否明确。
5. 敏感信息边界是否清楚: 哪些字段可展示、可存储、可进入日志或控制台，哪些只能后端内部处理。
6. 本次验证覆盖了哪些用户可见路径，哪些仍未验证。

小展示改动沿用项目现有组件、样式、请求和状态管理方式，不借机拆大组件、换库或引入新状态层。

## 2. 前端设计应用门槛

- 每个任务最多声明 1-2 个主导前端设计；更多先拆任务或降级为普通实现细节。
- 选用设计前先判断适用条件；不适用就拒绝。
- 必须产出应用证据；没证据视为没应用。
- 必须说明真实执行代价: 改多少文件、影响多少调用方、需要哪些验证、是否引入迁移 / 回滚 / 运行成本。
- 说不清收益、执行代价和失效边界时，沿用项目现状或局部直写。

## 3. 高 ROI 前端设计抓手

请求生命周期:

- 适用: 新增或修改异步请求、loading / empty / error / success、搜索、分页、筛选、刷新。
- 不适用: 纯静态展示、无异步数据的小样式改动。
- 应用证据: 请求生命周期表、失败展示、过期响应处理。

接口适配层:

- 适用: 字段名、状态码、错误结构、鉴权信息、后端兼容逻辑进入前端。
- 不适用: 单个局部私有字段，且没有复用和迁移风险。
- 应用证据: 字段映射表、默认值策略、临时兼容边界。

状态权威源:

- 适用: 组件本地、父组件、store、URL query、路由参数、后端、浏览器存储同时出现。
- 不适用: 当前组件独用的瞬时 UI 状态。
- 应用证据: 状态权威源表、同步方向、冲突时谁优先。

展示可信度:

- 适用: 任何图表、表格、统计数字和统计口径。
- 不适用: 纯静态文案、图标、装饰元素，不承载数据含义。
- 应用证据: 字段来源、单位、时间范围、统计口径、异常数据处理。

敏感信息边界:

- 适用: 前端接触鉴权状态、用户输入、浏览器持久化、富文本 / Markdown、第三方脚本或可见错误信息。
- 不适用: 无用户输入、无敏感数据、无持久化、无动态渲染的纯展示。
- 应用证据: 敏感字段清单、允许出现的位置、禁止出现的位置、脱敏或转义策略；固定危险 API 由静态工具补充拦截。

## 4. 小展示改动

只改文案、样式、局部布局、小展示 bug，且不改变接口、状态来源、图表数据、鉴权、安全或关键用户路径时，默认停在本文件。

最低证据:

- 说明未改变接口、状态来源和数据口径。
- 截图、局部手测、类型检查或组件测试择其一。
- 若实际触发接口、异步状态、图表、安全或关键路径风险，升级读取 details。

## 5. 读取 details

以下情况读取 `frontend.details.md`:

- 页面级编排、大组件拆分、复用组件边界变化。
- 新增状态层、缓存层、请求封装、全局错误机制或大规模组件体系。
- 请求生命周期、竞态、取消、局部错误边界复杂。
- store、URL、浏览器存储、后端数据之间存在权威源冲突。
- 图表、表格、统计口径复杂，或涉及多字段、多单位、多时间范围、多筛选条件。
- 涉及鉴权流程、敏感信息、HTML / Markdown 渲染、第三方脚本。
- 改关键业务页面、路由结构、全局错误处理、前端框架或构建工具。

details 只补充复杂前端设计；小展示改动不读取 details。
