# 桌面 GUI 体检

本文件用于桌面 GUI / 本地可视化工具的技术设计判断。重点不是罗列控件规则，而是把 GUI 设计落到可检查的证据: UI 状态表、线程边界、任务生命周期、错误恢复路径和诊断取证边界。

## 1. 默认判断

按重要程度先看:

1. UI 是否可能卡死，耗时任务是否离开 UI 线程。
2. 后台任务是否只通过框架推荐机制回到 UI 线程更新界面。
3. 用户看到的未开始、运行中、成功、失败、停止是否和真实任务状态一致。
4. 任务失败、用户停止、部分成功是否被区分。
5. 错误是否可恢复、可排查，且不泄露敏感内部信息。
6. 本次验证覆盖了哪些用户路径，哪些仍未验证。

小展示改动沿用现有 GUI 框架、窗口结构和项目风格，不借机重构窗口、替换框架或引入新任务模型。

## 2. GUI 设计应用门槛

- 每个任务最多声明 1-2 个主导 GUI 设计；更多先拆任务或降级为普通实现细节。
- 选用设计前先判断适用条件；不适用就拒绝。
- 必须产出应用证据；没证据视为没应用。
- 必须说明真实执行代价: 改多少文件、影响多少窗口 / 控件 / 任务、需要哪些验证、是否引入迁移 / 回滚 / 运行成本。
- 说不清收益、执行代价和失效边界时，沿用项目现状或局部直写。

## 3. 高 ROI GUI 设计抓手

UI 状态机:

- 适用: 多按钮、进度条、日志区、结果区互相影响，或任务有未开始 / 运行中 / 成功 / 失败 / 停止等状态。
- 不适用: 纯文案、布局、小输入校验且不改变任务状态。
- 应用证据: UI 状态表、控件启停规则、非法状态处理。

线程 / 任务边界:

- 适用: 文件读写、网络请求、批处理、模型推理、长计算、批量导入导出等可能阻塞 UI 的任务。
- 不适用: 毫秒级纯 UI 更新或无 IO 的简单计算。
- 应用证据: UI 线程负责什么、后台任务负责什么、回到 UI 线程的调度方式。

任务生命周期:

- 适用: 任务可运行、取消、停止、失败、部分成功、重试或关闭窗口时仍可能未结束。
- 不适用: 即时完成且无中间产物的单步操作。
- 应用证据: 生命周期表、中止信号路径、中间产物处理、失败项汇总。

错误恢复:

- 适用: 用户需要知道发生什么、影响什么、能做什么，或错误后可以重试 / 重新选择 / 返回上一步。
- 不适用: 内部不可恢复崩溃只需要终止并记录诊断。
- 应用证据: 用户提示、技术详情位置、恢复动作、敏感信息脱敏方式。

诊断取证:

- 适用: 内部工具、批处理工具、文件处理工具、有后台任务或用户需要协助排查的 GUI。
- 不适用: 极小一次性窗口且失败可直接复现。
- 应用证据: 最近错误、日志位置、任务状态、关键输入输出路径、可复制诊断信息。

## 4. 小展示改动

只改按钮文案、局部布局、显示 bug、小输入校验，且不新增后台任务、不改变任务生命周期、不改变危险操作时，默认停在本文件。

最低证据:

- 说明未改变任务状态、后台任务、关闭行为和危险操作。
- 截图、局部手测或相关轻量测试择其一。
- 若实际触发线程、任务生命周期、错误恢复、诊断取证或危险操作，按高 ROI GUI 设计抓手处理。

## 5. 鲁棒性验证

- 耗时任务要验证 UI 不阻塞、重复点击不会重复启动同一任务。
- 后台异常要能进入日志或诊断信息，并反馈到 UI。
- 用户停止和系统失败要在 UI、日志、状态中区分。
- 关闭窗口、取消任务、批处理部分失败要验证收尾路径。
- 跑不了时写入 taskwork 阶段总结的“未验证”，说明原因和剩余风险。
