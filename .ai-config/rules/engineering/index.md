# 专题索引: 代码语义

本专题保留设计模式参考菜单、非静态语义审查参考和分语言细则。审查的触发与门禁逻辑在 `AGENTS.md § 6`，本专题不重列。

## 触发入口

### 设计模式参考菜单

`code.index.md` 是**参考菜单，不是约束**，写完代码判断要不要引入抽象时按需翻阅：

- 写完一轮代码后，静态工具或 diff 暴露结构坏味道，需判断局部修还是范式治理。
- 命中状态机、策略、注册表、错误层级、端口 / 适配器等范式取舍。
- 子 agent 复核报告字段也在此文件。

结构是可逆的形状，默认 defer 到 `process/loop.index.md` 的 P4，有真实复杂度信号才翻阅，不作为启动前默认设计仪式。

### 跨语言与分语言细则

多语言或语言专属要点按需读取（对应 `AGENTS.md § 9`）:

- 跨语言契约 / 边界 / 严谨度参考 → `polyglot.index.md`
- TypeScript → `typescript.index.md`
- Go → `go.index.md`
- Python 工具链 → `tooling.registry.toml`

## 读取边界

- 机械格式、lint、类型、基础测试优先交给工具，不在 Markdown 中展开。
- 架构、API、Web 前端、GUI 等交付体检规则在 `delivery/`。
- 老项目小改优先读相关代码和影响面；只有写后命中结构坏味道或高复杂度时才翻 `code.index.md`，不借机升级架构或重写范式。
