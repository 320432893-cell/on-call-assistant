# 架构体检

本文件用于既有项目准备 GUI 化、Web 化、CLI 化、服务化，或脚本长期化前的架构体检。

目标不是设计全新架构，而是找出当前代码哪里不适合承载长期入口，哪里需要先解构。

## 1. 体检对象

默认检查：

- 核心处理逻辑是否和入口、UI、Web、CLI、文件 IO 混在一起。
- 是否存在多个入口重复编排同一业务流程。
- 配置、路径、URL、阈值、secret 是否散落在业务逻辑里。
- 外部服务、数据库、文件系统、第三方 SDK 是否穿透核心逻辑。
- source of truth 是否清楚。
- degraded / 回退是否清楚。
- 关键逻辑是否能脱离入口独立测试。

## 2. 解构优先级

按重要程度排序：

1. 先拆核心逻辑和入口：核心逻辑变成可独立调用的函数或模块。
2. 再拆 IO 和外部适配：HTTP、SDK、数据库、文件系统、消息队列放到适配层。
3. 再拆配置：环境差异、路径、URL、阈值、开关走配置注入。
4. 再拆重复编排：多个入口重复的流程收敛到服务 / 编排层。
5. 最后考虑公共复用：第二次跨入口重复时考虑抽取，第三次重复时优先抽取。

## 3. 建议边界

入口层：

- 只做参数解析、配置加载、依赖装配、启动。

服务 / 编排层：

- 组织业务流程。
- 调用核心逻辑、仓储、外部适配器。
- 处理业务级错误和回退决策。

核心逻辑层：

- 处理纯计算、纯转换、核心业务规则。
- 输入输出使用普通数据结构或明确模型。
- 不依赖 UI / Web / CLI 框架对象。

外部适配层：

- 封装 HTTP、SDK、数据库、文件系统、消息队列。
- 不把第三方细节泄漏到核心逻辑层。

## 4. 关键判断

需要先停下来讨论的情况：

- 核心逻辑依赖 GUI / Web / CLI 框架对象。
- 入口层承载大量业务流程。
- 同一流程在多个入口重复编排。
- 外部服务失败会污染 source of truth。
- 无超时、无限重试或不幂等操作直接重试。
- 配置和 secret 进入代码、日志或文档。
- 改动会影响公共接口、核心签名、跨模块契约或部署方式。

## 5. 输出

体检输出只保留：

- 当前最不合理的 1-3 个边界问题。
- 推荐先解构的 1-3 个位置。
- 本次不处理的范围。
- 解构后必须验证的关键路径。
