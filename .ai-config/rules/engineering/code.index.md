# 设计模式参考菜单 + 子 agent 审查规范

本文件有两个用途：
1. 执行态写完代码后，按需判断是否引入抽象。
2. 子 agent 审查时，按本文件执行复核并输出报告。

T0 任务、一次性脚本、临时排查脚本不开本文件。老项目小改优先保持局部一致，不借机引入新范式。

## § 应用证据（引入任何抽象的唯一闸）

引入任何抽象 MUST 产出，否则视为没应用：
- 它解决的具体复杂度是什么（要有代码证据）
- 真实执行代价：改多少文件、影响多少调用方、测试/迁移/回滚成本
- 什么情况下这个抽象会失效或变成负担

每轮最多评估 1-2 个主导抽象；说不清上面三点 → 回到直写或沿用现有风格。

## § 设计抓手菜单

| 抓手 | 适用 | 不适用 | 应用证据 |
|---|---|---|---|
| 不变量 | 业务规则必须始终成立 | 临时计算、无跨步骤约束 | 不变量列表 / 何时检查 / 违反后处理 |
| 命令/查询分离 | 读写混在一起，调用方难判副作用 | 一次性脚本、副作用清楚的私有函数 | 命令清单 / 查询清单 / 副作用边界 |
| 状态机 | 多布尔互相影响、非法组合可能出现 | 仅两个稳定状态且无非法转移风险 | 状态列表 / 合法转移表 / 非法转移处理 |
| 策略/注册表 | key 路由、三类以上可扩展分支 | 分支固定、差异过大、共享接口别扭 | key→handler 映射 / 统一输入输出 / 未知 key 处理 |
| 端口/适配器 | 外部依赖需替换、mock、隔离失败 | 单一调用点、无替换需求 | 抽象边界清单 / 核心依赖什么 / 适配器负责什么 |
| 结果/错误模型 | 多种失败原因会被调用方分流 | 仅顶层展示错误、调用方不分流 | 错误类别 / 调用方处理方式 / 哪些继续抛 |
| 流水线/CQRS | 多阶段处理、读写模型天然分离 | 单阶段线性逻辑、小功能 | 阶段 / 规则 / 读写模型边界 |
| 减少无效工作 | 循环内有全表扫描/重复构造/无前置剪枝 | 数据量小、单次调用 | ① 问题边界：工作范围是否收窄到当前问题 key 而非全量数据；② 预计算：循环内重复构造的东西是否提到循环外；③ 剪枝：进入昂贵计算前是否有廉价可行性判断（候选为空/数量不足直接跳过）；④ 查找定位：有无利用已有结构（索引/字典/有序性/层级关系）直接定位，而非全局遍历/无剪枝递归；全局遍历和无剪枝递归须说明理由，不是默认手段 |
| 算法选择 | 数据规模增长后减少无效工作已到天花板、当前复杂度无法突破 | 实现低效但算法复杂度合理（先做减少无效工作）| 当前算法复杂度 / 瓶颈在哪一步 / 候选算法复杂度对比 / 换算法的业务逻辑影响范围 |

## § 子 agent 复核报告

中高风险或阶段闭包时触发，输出以下字段：

| 字段 | 内容 |
|---|---|
| 坏味道 | 重复逻辑 / 过长函数 / 深层嵌套 / 魔法数字 / 命名不表达业务意图 |
| 副作用风险 | 外部状态/持久化/并发/重试/异常处理的失败模式；无则 N/A |
| **返回结构一致性** | **有多个返回分支的函数（正常/异常/空数据/部分成功）：所有分支的返回结构必须包含相同的顶层字段；缺字段的分支视为缺陷，不得 defer** |
| **幂等性** | **有写入/调用外部服务/DB操作的函数：重复执行结果是否一致？重复触发的入口（重试/用户重复提交/消息重投）是否有防护？无写入则 N/A** |
| **部分成功处理** | **有批量操作的函数：前N条成功第N+1条失败时，是全部回滚还是保留已成功部分？调用方能否区分这两种结果？未声明策略视为缺陷** |
| 契约合规 | 实现是否符合验收动作/业务口径/SSOT；有无隐性假设未在假设列表 |
| 设计模式 | 当前结构是否有值得替换的模式；改动成本高时记入 defer 项，不强制 |
| 扩展性 | 当前实现是否阻塞未来扩展 |
| 错误信息 | 业务异常：是否翻译成业务语言，含字段/期望值/实际值/用户下一步（反例：「未找到匹配记录」不达标，须具化到是订单缺失还是单价不符）；程序异常：catch 块是否附业务上下文（批次/行号/关键字段）+ 异常栈；调试信息：是否走 DEBUG 级别且受模块开关控制；多输出目标（logger/callback/文件）：MUST 明确哪些信息进哪个目标，不得只接一条路由导致日志断层 |
| 重构 ROI | 改 vs 不改的代价/收益 |
| 结论 | 通过 / 有限通过（列 defer 项）/ 必须重构 |

复核重点（静态工具覆盖不到的部分）：
- **【高权重】幂等性**：每个有副作用的函数，列出所有可能重复触发的入口（重试/重投/用户重复操作），逐一说明防护手段；无防护 → 必须重构，不得 defer
- **【高权重】部分成功**：每个批量操作，明确回滚策略（全部回滚 / 保留已成功 / 补偿）；调用方必须能区分"全失败"和"部分成功"；策略未声明 → 必须重构，不得 defer
- **【高权重】查找定位**：每个查找/遍历逻辑，是否有可用的已有结构（索引/字典/有序性/层级）可直接定位；全局遍历/无剪枝递归须说明理由，无理由 → 记入 defer 项
- 真实运行路径：正常/失败/取消/重试/并发/降级是否闭合；异步操作的重试逻辑 MUST 区分"操作未发生"和"操作已发生但未完成"——两者恢复路径相反，用 URL/DOM/响应特征等客观信号判断当前状态，不得仅凭判断超时推断
- 状态与数据生命周期：SSOT/缓存/写入顺序/脏数据/回滚
- 公共行为：返回结构/异常语义/副作用/调用方兼容/迁移成本
- 外部依赖边界：SDK/IO 是否穿透核心，可否替换/mock/隔离
- 长期维护：新增分支/handler/状态组合/配置散落/测试替换难度
