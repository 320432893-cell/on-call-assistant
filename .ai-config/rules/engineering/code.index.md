# 设计模式参考菜单（tier2，按需翻阅）

本文件是**设计模式参考菜单**，不是约束。写完代码后判断“要不要引入某抽象”时按需翻阅。它唯一生效的闸是 `§ 应用证据`——没证据视为没应用。审查触发见 `AGENTS.md` 完成卡，常驻卡口见 `AGENTS.md` 四个常驻卡口，本文件不重列。

定位边界：
- 它治理脏代码 / 坏代码，**不是项目启动前的默认设计仪式**。结构（解耦、抽象、范式）是可逆的形状，默认 defer；有真实复杂度信号才翻本文件。
- 小改、一次性脚本、测试代码、临时迁移 / 排查脚本不开本菜单。
- 老项目小改优先保持局部一致，不借机引入新范式；本文件不得压过 `AGENTS.md` 的局部一致性、用户拍板和影响面判断。

---

## § 应用证据（唯一的闸）

引入任何抽象 MUST 产出应用证据，否则视为没应用：

- 它解决的**具体复杂度**是什么（要有代码证据，不凭空套）。
- 真实执行代价：改多少文件、影响多少调用方、增加多少测试 / 迁移 / 回滚成本。
- 什么情况下这个抽象会**失效或变成负担**。

每轮结构复盘最多 1–2 个主导抽象；更多先拆任务或降级为普通实现细节。说不清上面三点 → 回到直写或沿用现有项目风格。

## § 设计抓手菜单

总纲：下列范式本质同源——**让依赖指向抽象，把易变点和副作用推到边界**。遇到清单外的新场景，按此原理推导该不该抽象，而非在清单里找名词匹配。

| 抓手 | 适用（出现这种真实复杂度才用） | 不适用 | 应用证据 |
|---|---|---|---|
| 不变量 | 业务规则必须始终成立（金额非负、状态转移合法、缓存与源一致） | 临时展示计算、无跨步骤约束 | 不变量列表 / 何时检查 / 违反后如何处理 |
| 命令 / 查询分离 | 读写混在一起，调用方难判有无副作用 | 一次性脚本或局部私有函数，副作用清楚 | 命令清单 / 查询清单 / 副作用边界 |
| 状态机 | 多布尔互相影响、生命周期分散、非法组合可能出现 | 仅两个稳定状态且无非法转移风险 | 状态列表 / 合法转移表 / 非法转移处理 |
| 策略 / 注册表 | key 路由、多 handler、三类以上可扩展分支 | 分支固定、差异过大、共享接口别扭 | key→handler 映射 / 统一输入输出 / 未知 key 处理 |
| 端口 / 适配器 | 外部依赖需替换、mock、隔离失败 | 单一调用点、无替换需求 | 抽象边界清单 / 核心依赖什么 / 适配器负责什么 |
| 结果 / 错误模型 | 多种失败原因会被调用方分流处理 | 仅顶层展示错误、调用方不分流 | 错误类别 / 调用方处理方式 / 哪些继续抛 |
| 流水线 / 解释器 / CQRS | 多阶段处理、可组合规则、读写模型天然分离 | 单阶段线性逻辑、小功能 | 阶段 / 规则 / 读写模型边界，择一 |

选择指引：复杂度来自**状态组合**→状态机；来自 **key 路由 / handler 扩展**→策略 / 注册表；来自**外部依赖穿透核心**→端口 / 适配器；来自**失败分流**→结果 / 错误模型；来自**读写副作用混杂**→命令 / 查询分离。

抽象层级：通用层默认只做少数稳定判断（不变量识别、命令查询分离、错误是否显式建模）；任务层（状态机 / 策略 / 端口适配器 / 流水线 / CQRS）按需激活，不适用就拒绝。

## § 子 agent 复核报告字段

（触发见 `AGENTS.md` 完成卡）

| 字段 | 内容 |
|---|---|
| 坏味道 | 结构 / 耦合 / 抽象错位 / 控制流 / 复杂度 |
| 副作用风险 | 触及外部状态、持久化、并发、外部依赖、重试或异常处理时给失败模式与缓解；无则 N/A |
| 扩展性 | 当前实现是否阻塞未来扩展 |
| 重构 ROI | 改 vs 不改的代价 / 收益 |
| 结论 | 通过 / 有限通过 / 必须重构 |

复核重点（静态工具看不到或只能弱提示的部分）：真实运行路径（正常 / 失败 / 取消 / 重试 / 并发 / 部分成功 / 降级是否闭合）、状态与数据生命周期（SSOT / 缓存 / 写入顺序 / 幂等 / 重复写 / 脏数据 / 回滚）、公共行为（返回结构 / 异常语义 / 副作用 / 调用方兼容 / 迁移成本）、外部依赖边界（SDK / IO 是否穿透核心、可否替换 / mock / 隔离）、安全与隐私语义（哪些字段可记录 / 返回 / 展示 / 持久化）、长期维护（新增分支 / handler / 状态组合 / 配置散落 / 测试替换难度）。
