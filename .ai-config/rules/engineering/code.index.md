## §1 应用证据闸(引入任何抽象的唯一闸)〔变更〕〔注意〕
引入任何抽象 MUST 产出三点,否则=没应用,回直写或沿用现风格:
1. 解决的具体复杂度(要有代码证据)
2. 真实代价:改多少文件 / 影响多少调用方 / 测试·迁移·回滚成本
3. 何时失效或变负担
每轮最多评 1-2 个主导抽象;说不清三点=不引。
(抽象是变更成本的双刃:对的让后期便宜改,错的/早的=债 + 让读者多解析一层。)

## §2 设计抓手菜单
每行:适用 / 不适用(同等重要) / 应用证据。

| 抓手 | 适用 | 不适用 | 应用证据 |
|---|---|---|---|
| 不变量 | 业务规则必须始终成立 | 临时计算、无跨步骤约束 | 不变量列表/何时检查/违反处理 |
| 命令查询分离 | 读写混、调用方难判副作用 | 一次性脚本、副作用清楚的私有函数 | 命令清单/查询清单/副作用边界 |
| 状态机 | 多布尔互相影响、可能出非法组合 | 仅两稳态、无非法转移 | 状态/合法转移表/非法转移处理 |
| 策略·注册表 | key 路由、≥3 类可扩展分支 | 分支固定、差异过大、共享接口别扭 | key→handler/统一输入输出/未知key处理 |
| 端口·适配器 | 外部依赖需替换/mock/隔离失败 | 单一调用点、无替换需求 | 抽象边界/核心依赖什么/适配器负责什么 |
| 结果·错误模型 | 多失败原因被调用方分流 | 仅顶层展示、调用方不分流 | 错误类别/调用方处理/哪些继续抛 |
| 流水线·CQRS | 多阶段、读写模型天然分离 | 单阶段线性、小功能 | 阶段/规则/读写模型边界 |
| 减少无效工作 | 循环内全表扫/重复构造/无前置剪枝 | 数据量小、单次调用 | ①问题边界:收窄到当前key非全量 ②预计算:循环内重复构造提到循环外 ③剪枝:进昂贵计算前有廉价可行性判断(候选空/不足直接跳) ④查找定位:用已有结构(索引/字典/有序/层级)直接定位;全局遍历/无剪枝递归须给理由,非默认 |
| 算法选择 | 减少无效工作已到天花板、复杂度无法突破 | 实现低效但复杂度合理(先做减少无效工作) | 当前复杂度/瓶颈在哪步/候选复杂度对比/换算法的业务影响范围 |

## §3 子 agent 复核(中高风险或阶段闭包触发)
**判定档**:通过 / 有限通过(列 defer) / 必须重构 / **无法判定(原因)→升级用户 或 标"需运行时验证"**。
第四档存在的理由:幂等性这类常**读代码判不出**(取决于外部服务语义/隔离级别),逼模型给假自信结论比说"我不知道"更危险。**判不出就说判不出,别猜。**

**编排:复核规模随 blast-radius,非一刀切单遍**〔发现〕〔注意〕(用力分配见 AGENTS.md §2):
- 低(可逆/单点/无外部写):单遍复核即可,别 fan-out 烧 token。
- 高(不可逆/上游被依赖/外部写/并发):fan-out ≥3 个独立子 agent,每个换一个 lens(正确性 / 安全·并发 / 可复现),各自独立出结论 → 多数表决;分歧项升级用户,不取"看起来对"那条。
- 一个 context 装不下的活(全仓审计/迁移/diff 比对):按子任务 fan-out 读 → 每条结论再派一个独立 agent **对抗核实(试图证伪)** → 只有坐实的浮上来。
- 教训:单个子 agent 会自信地编结论(本规则系统就被逮到过一次)。**对抗校验是高 blast-radius 的默认,不是可选项。** 收敛后只把坐实结论交主上下文/用户。

**高权重三项改成"要一个测试",不是"读代码判断"**〔发现〕——能跑出来的正确性别留给眼力:

| 项 | 要的测试(挂 pytest) | 判不出时 |
|---|---|---|
| 幂等性(有写入/调外部/DB) | 同输入连调 2 次,副作用计数=1 / 结果稳定 | 无法判定→需运行时验证 |
| 部分成功(批量) | 注入第 N+1 条失败,调用方能区分 全失败 vs 部分成功 + 回滚策略生效 | 无法判定→升级 |
| 返回结构**可判别** | 多分支(正常/异常/空/部分):调用方有稳定方式区分(相同顶层字段 **或** 判别 tag) | —— |

> 旧版"返回结构字段完全相同、不得 defer"松绑为"**可判别**"——给 Result/tagged-union(分支形状本就不同、靠 tag 区分)留路。

**测试模板**:
```python
# 幂等性:连调 2 次,副作用只一次、结果稳定
def test_<op>_idempotent():
    spy = install_side_effect_spy()      # DB 写/外部调用计数
    <op>(input); s1 = snapshot_state()
    <op>(input); s2 = snapshot_state()   # 模拟重试/重投/重复提交
    assert spy.effect_count == 1
    assert s1 == s2
# 部分成功:第 N+1 条失败,调用方可区分、回滚与声明一致
def test_<batch>_partial_failure():
    res = <batch>([ok, ok, BAD, ok])
    assert res.kind in ("all_failed", "partial")
    assert committed() == expected_for(res.kind)
```

**其余字段**:
- 坏味道(只查工具判不了的语义味道)〔注意〕:命名不表达业务意图 / 重复**业务**逻辑。魔法数字·过长函数·深嵌套→radon·ruff·semgrep(registry),不在此重复。
- 代码身份(语义层)〔变更〕:入口是否**真薄** / 正式能力是否反依赖 tools·tests·archive·scripts·devtools / 非正式区是否带 `# lifecycle:` 身份(短命探针带 expires·长寿工具住 devtools/) / 存量是否新增正式能力。**设计=AGENTS.md §3,机械=registry(code-identity·lifecycle baseline 棘轮),本字段=三者里的语义查**;职责混杂或反依赖→不得通过。
- 错误信息〔发现〕:业务异常含 字段+期望+实际+用户下一步(反例:"未找到匹配记录"不达标,须到"订单缺失还是单价不符");catch 附业务上下文(批次/行号/关键字段)+栈;调试走 DEBUG+模块开关;多输出目标须明确哪条信息进哪,不留日志断层。
- 可观测性(语义层;**仅当本切片碰 API handler / 后台·长任务 / 队列 / 健康检查端点才查**,纯算法/纯计算切片 N/A)〔发现〕:① request_id 能跨 响应头·错误体·服务端日志 三处对齐(不只是响应头有一个);② 健康检查区分 整体/关键路径/外部依赖,依赖失败降级为可诊断状态而非整体 500;③ 新增 后台任务/长任务/队列/外部调用/DB写入 给失败定位线索(日志名/任务ID/输入摘要/重跑入口 四选二)。机器形态(错误响应稳定形状·不泄栈·结构化日志·error_code 登记)→semgrep·check_error_catalog,不在此复查。
- 契约合规:符合验收动作/业务口径/SSOT;隐性假设是否已登记。
- 副作用风险 / 扩展性 / 设计模式(改成本高→记 defer 不强制) / 重构 ROI。

**复核重点(静态工具覆盖不到的)**:
- 真实运行路径闭合:正常/失败/取消/重试/并发/降级〔发现〕。
- **异步重试 MUST 区分"操作未发生" vs "操作已发生未完成"**——恢复路径相反,用 URL/DOM/响应特征等客观信号判,不靠超时推断〔发现〕。
- 状态与数据生命周期:SSOT/缓存/写入顺序/脏数据/回滚。
- 公共行为:返回结构/异常语义/副作用/调用方兼容/迁移成本〔变更〕。
- 外部依赖边界:SDK/IO 是否穿透核心、可否替换/mock/隔离〔变更〕。

**结论**:四档之一。

## §4 拆分专项检查〔变更〕
拆分后**乐观运行**(跑测试/调用方),**实际与预期不符才进对应项**,不逐项前置——这是 run-and-observe,把判断锚在可观测信号上。
- 老调用:全局搜原 文件名/类名/函数名,逐一确认调用方更到新路径
- 循环依赖:新文件间互相引用=边界划错,重新拍板
- 接口完整性:原对外 export/public 在新文件全可寻,缺一=未完成
- 重复逻辑:多文件出现相似段→合并公共模块,非各自复制
- 测试覆盖:原测试仍过;依赖原结构的测试路径 MUST 同步更新
- 兼容别名:MUST 注释清理条件(`# 兼容别名:待 xxx 更新后删`)+闭包 defer 登记,不得无限期(生命周期见 AGENTS.md §3)
- MRO 冲突:多继承/mixin 同名方法→优先删占位声明(`raise NotImplementedError` 在 mixin 是设计味,抽象该由 ABC 担);删不掉才调继承顺序,真相源 mixin 排占位 mixin 前
