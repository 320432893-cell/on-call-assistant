# 代码语义规则索引

本文件只做通用代码语义路由。默认停在本文件，不自动读取 `code.details.md`。

## 1. 文件定位

触发:

- 写业务代码、修 bug、小功能、局部重构。
- 修改公共接口、异常、日志、配置、测试语义。
- 不确定是否命中 architecture / backend / frontend / GUI 专题规则。

动作:

- 先判断行为、数据流 / 状态流、公共契约、失败路径和验证方式。
- 小改优先沿用项目现状，不借机引入新范式。
- 老项目中，本文件不得压过 `../process/flow_legacy_project.index.md` 的局部一致性和影响面判断。

## 2. 默认轻量判断

默认只做以下判断，不读取 details:

- 本次行为是否正确。
- 数据流 / 状态流是否清楚。
- 公共契约是否被破坏。
- 失败路径是否可见、可恢复、可排查。
- 验证方式是否覆盖本次真实风险。
- 新抽象牺牲了什么，是否值得。

小改边界:

- 纯文案、样式微调、单点常量、注释、无行为变化的小改，不读取 details。
- 小改不做全量架构审查，不输出完整规则清单。
- 如果小改实际触发公共契约、外部依赖、异常路径、配置、状态生命周期，升级读取 details。

## 3. 读取 details

命中以下任一场景，读取 `code.details.md`:

- 新增或修改命名，且命名影响业务职责理解。
- 涉及 IO、数据库、HTTP、文件、外部 API、mock、可替换实现。
- 涉及生命周期、多布尔值、非法状态组合、状态判断散落。
- 涉及 key 路由、多 handler、多分支扩展。
- 涉及 try/except、错误类型、错误边界、降级。
- 涉及异常分支、外部调用、状态转移、排障信息。
- 涉及环境变量、secret、运行时开关、部署差异。
- 涉及公开函数、跨模块调用、API 请求 / 响应、返回结构、异常类型、副作用。
- 修 bug、新增公共行为、修改异常路径、配置、状态生命周期、策略分支或公共契约，需要判断测试语义。

读取边界:

- details 里的范式不是默认套用清单；只使用当前任务命中的章节。
- 不因为普通代码改动就全量读取 details。
- 已由 Ruff / basedpyright / import-linter / pytest 稳定检查的事项，不写成 AI 自觉规则。

## 4. 下一步规则路由

- 涉及架构边界、依赖方向、source of truth 时，读取 `architecture.index.md`。
- 涉及 FastAPI / Starlette / HTTP API 时，读取 `backend.index.md`。
- 涉及 Web 前端组件、状态、API 调用、图表数据时，读取 `frontend.index.md`。
- 涉及桌面 GUI、UI 线程、后台任务时，读取 `gui.md`。
- 涉及数据写入、覆盖、合并、对账时，读取 `../delivery/data.index.md`。
