# 审查触发与节奏（tier1，按需读；细则在 daily/stage，宪法触发指针见 AGENTS §3）

触发：要做体检时读；定"何时审、审到哪层、谁批"。

**核心 why**：旧四门把 `[复核]` 挂在"切片/阶段**闭包**"——那是要人**察觉**的判断事件，必不可靠（这是死码/双源长期累积的真因）。本规范把它改成 **`[复核]` 由人按进度主动触发，机器只供 scope**。分工铁律：

- **何时审 = 人**：进度知识机器拿不到，不可替（用户能判进度）。
- **承重识别 = 机器扇入**：用户自认判不准承重，故归机器（fan-in），非人眼。
- **放行登记批准 = 人**：白名单/skip/debt 的"接受违规"是用户专属权，AI 只提议+证据；闸红着逼审（职责分离：被闸管的 AI 不能自批豁免）。
- **行为安全 = 测试**：语义承重残差（少调用大影响）不靠判断，靠测试跑红。
- **微观纪律 = 机器闸**：git 事件自动（见 AGENTS §3），不靠记忆。

## §1 成本铁律：成本 ∝ 频率的倒数
你越常做的越便宜；贵活只挂最少做的触点。**per-commit 永不放全仓扫描**（破这条=改变贵=被绕过）。
| 触点 | 频率 | 跑什么 | 成本 |
|---|---|---|---|
| per-edit | 几百次/天·hook | py_compile+ruff 单文件 | 毫秒 |
| 自动 commit | 几十次/天·hook | ruff staged+dup-symbol+import-linter；编译过即提工作分支 | 亚秒；非语法只 flag 不 block |
| **每日体检** | 1/天·**人触发** | daily.md：机器闸+死码+扇入+漂移 | 秒级 |
| **阶段体检** | 里程碑·**人触发** | stage.md：+L1–L3 子agent对抗 | 分钟级+token |

## §2 五层优先级 + 每层裁判（越上越影响架构、越没工具）
审查从上往下；上层没过别花力气下层（地基不稳清死码无意义）。
| 层 | 审什么 | 裁判 |
|---|---|---|
| L1 依赖方向/分层 | 无环·无反向依赖·契约设计对不对 | import-linter（守契约）+ **人定契约本身对不对** |
| L2 归属/SSOT | 双源·弃用旧路径·入口真薄 | def/class 名近似+签名+**扇入**叉乘（近名+一死=删候选）；不同名→子agent对抗 |
| L3 契约/不变量 | 公共返回·错误语义·幂等·部分成功可判别 | **真测试**（§3 那套，跑出来不靠读） |
| L4 死码+形状 | 公开零调用·圈复杂度·行数 | vulture/grimp扇入/radon（严格闸） |
| L5 局部整洁 | 未用 import·命名·魔法数 | ruff/check_naming |

**警告：绿 sweep ≠ 架构无恙，只证 L4/L5。** L1–L3 工具够不到，靠人触发的分层审。

## §3 你贴哪份
- 收工 → `daily.md`（地板：机器+死码+漂移，浅而广，不碰设计层）。
- 切片闭包/交接前/合 main 前/要动大东西 → `stage.md`（顶层：+L1–L3 子agent对抗，深而按扰动面 scope）。

两份结尾都产出：**待办清单 + 白名单/skip 的 pending（待你批，闸红着逼审）+ 漂移快照**。
