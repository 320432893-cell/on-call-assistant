# 规则专题索引

本目录按专题入口读取规则，不默认全量读取所有 `*.md`。

使用原则:

- 先选专题入口，再按入口里的触发条件读取具体规则文件。
- 专题入口只做路由和批量维护分组，不复制具体规则正文。
- 已读本文件后仍不确定当前任务属于哪个专题时，先读取 `process/index.md`；仍不确定时问用户一句。
- 新任务、任务目标变化、从讨论进入实现、从实现进入验证 / 交付、用户纠偏或上下文压缩后，必须重新从本文件或阶段闭包里的 `RULE_ROUTE` 判断规则入口。
- 不因为存在 `*.details.md` 就读取 details；只有专题 index 命中复杂、高风险、正式交付或副作用条件时才读取。

专题入口:

- `process/index.md`: 通用执行、接手、新项目、老项目、救火。
- `reasoning/index.md`: 信息缺口、风险识别、用户反驳、假设推进。
- `rule_governance/index.md`: 规则维护、规则治理、hook / lint / CI / settings。
- `engineering/index.md`: 代码语义、架构、后端、前端、GUI。
- `delivery/index.md`: 用户交互、数据处理、打包交付、浏览器自动化。

批量维护顺序:

1. 先维护 `rule_governance/index.md`，确认规则怎么改。
2. 再按专题入口批量检查触发条件、读取路径、牺牲项和反模式。
3. 最后只修改命中的具体规则文件，不因索引存在而全量重写。
