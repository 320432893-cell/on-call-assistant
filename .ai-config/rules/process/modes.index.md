# 工作模式（tier1）— 三真相源

判**这一步靠什么裁决**（与 `AGENTS.md § 4` 三态机管的“这条信息能不能动”正交，两轴不混）。

不按“项目类型”分类（清单必漏），按一句**生成式问句**分类——这才是通用的来源：

> **这一步的真相源是什么？它会不会骗我？**

| 模式 | 真相源 | 会骗你吗 | 头号死法 | 引擎 |
|---|---|---|---|---|
| 建造 build | 领域真相 + oracle | 否（oracle 独立时） | 结构错 | `loop` 八槽 + 契约门 |
| 困难 probe | 外部现实（那个外部系统） | 否，但**查询贵 + 规律未知** | **过早发散** | 刻画失败边界 |
| ML | 统计评估 | **会，天天会** | 指标在骗你 | 对抗式评估 |

---

## 模式探测器（每步探一次，不是开工选一次）

下一步是「把信息找出来 / 铺开」还是「基于已有信息往下推」（探查 vs 编织，见 `dispatch`）。探查再分：

- **读已存在的信息**（文件 / 仓库 / 可搜文档）→ 偏建造，可派子 agent。
- **造还不存在的信息**（对现实跑实验逼出未知）→ 困难模式，通常**不能干净委托**，主线亲自跑 predict → run → learn。

**模式翻转触发器 = 故障单列**：建造模式里同一步连续失败，不是再 patch，是信号说**模式判错了**——你以为知道怎么做，其实不知道。立刻停执行链，翻入困难模式做诊断步。断链 → 改 → 无响应 → 改 → 再断 的死亡螺旋，正是没翻转、在建造模式里硬 patch 一个困难问题。

故障 MUST 单列：故障、异常、现象不一致、用户反馈不符预期，单独作为一步处理，不混在正常推进里；同一小步连续失败 MUST 停止执行链进故障步，不得继续试跑；故障结束 MUST 重新评估策略，不默认沿用故障前方案。

## 困难模式纪律（治“过早发散”，nc_auto 的教训）

困难模式真正的死法不是坚持太久，是**过早发散**——把一次失败误读成“路死了”，换路就扔掉了失败教的信息，信息不积累就永远找不到规律。

引擎 = **刻画失败边界直到规律浮现，发散是最后手段**：

- 每次失败 MUST 产出一条**诊断**（一条关于这个系统的新事实）才允许下一个动作。
- **换一条根本不同的路，MUST 先有诊断证明当前路确实死了**（落到 `AGENTS.md § 4` 困难态 + 用户拍板）。“感觉卡住”不是证据。
- **每次失败前先写预测**（“我预期发生什么”），让现实投票推翻它。不预测就读不到这个数据点。这里 AI“自信地编个解释”最危险——没有契约可对，只有现实，而现实查起来贵、编理论很便宜。
- **小步**是困难模式可幸存的结构机制：把每条错路的沉没成本钉到很小，让回退、换角度刻画变便宜。
- **翻转点的契约门**：当“现在能跑了”出现，这是全项目最危险的一刻（“它通了”≠“我懂它为何通”）。MUST 先证明**能被故意复现**（按预期成功、也按预期失败）→ 把“怎么稳定驱动”锁成契约写进**项目 rule 文件**（已证死的路 / 已证活的咒语 / 每个探针教了什么）→ 然后才翻入建造模式往上建。承重的“已证死 / 已证活”MUST 进加载上下文，不能只“可检索”（召回静默失败 = 又去试死路）。

## ML 模式纪律

ML 是“高爆炸 × 低可检测”的最纯实例：指标便宜到一跑就有，却系统性地骗你（泄漏、过拟合验证集、训练 / 服务特征不一致、分布漂移）。

- `AGENTS.md § 6.2` 三边界整体迁移：入口 = 数据（泄漏？训练分布 = 服务分布？）；产出 = 泛化（指标真泛化还是自欺？怎么独立证伪？）；出口 = 漂移与回滚。
- **该锁的契约层**（不碰不确定性，必须先锁）：数据切分（尤其时间切分防泄漏）、评估协议 + 留出集、训练-服务特征一致性（防 skew = 防双真相源）、“够好”的阈值（业务能容忍多大错，**只有用户知道**）。
- **该迭代的形状**：用哪些特征、模型选型、超参——信号驱动。
- **独有纪律 = 对抗式评估**：主动证明“我这个漂亮指标是假的”（查泄漏、在真正未来的时段验、查训练-服务一致）。
- 修正“ML 结构不重要”：模型结构次要，但**数据 / 评估 / 管道结构比平时更重要**——静默杀手（泄漏、skew、不可复现）全是管道的结构属性，“模型能跑”一个都看不出来。

## 第四真相源（开放槽）

三模式不保证穷举。遇到真相源装不下三种的（如**并发 / 分布式**：真相源是非确定时序，既会撒谎又观测即改变），按生成式问句现场推导，不硬塞进三模式。**通用的不是这张表，是那句问句。**
