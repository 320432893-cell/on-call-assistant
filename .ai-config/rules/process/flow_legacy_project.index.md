# 既有项目索引

既有项目的不确定性在过去。AI 可以读代码、识别模式、追影响面；不能替用户推断历史意图。

## 1. 先分任务类型

默认先判断本次属于哪一类：

- 小改：局部 bug、局部行为调整、文案、配置、单点逻辑；默认停在本 index。
- 重构 / 大改：跨模块调整、公共接口变化、数据流变化、架构边界变化；读取 details。
- 加新功能：在既有结构上新增能力；跨模块、新数据/状态/权限/外部依赖、新子系统时读取 details。
- 稀有救火：线上故障、生产事故、数据损坏、安全风险、继续试错可能扩大损害；先走止损。

## 2. 项目记忆层

先检查是否已有：

- `docs/PROJECT_MAP.md`
- `docs/AI_HANDOFF.md`

处理：

- 已有则先读，发现明显过期再更新。
- 没有时，小改不强制补完整文档。
- 重构 / 大改 / 加新功能需要补最小项目地图。
- 大项目只围绕本次任务抽样，不做全盘扫描。

最小项目地图只记录：

- 项目用途和不做什么。
- 入口、运行方式、测试方式。
- 本次已查看范围和未查看范围。
- 相关目录职责。
- Source of truth。
- 已知雷区和未验证项。

最小接力记录只记录：

- 当前任务目标、状态和用户已拍板内容。
- 已验证项。
- 未验证项。
- 下次接手先看哪里。

## 3. 事实分栏

老项目里所有关键判断必须区分：

- 已验证：来自代码、grep、静态分析、测试或命令输出。
- 推断：来自局部上下文，但未被证据直接确认。
- 未知：历史意图、隐性契约、生产数据形态、边缘调用方。

规则：

- 调用关系、数据流、影响面必须用 grep / 静态分析验证。
- “为什么当初这么写”默认归入未知。
- 未知不能写成事实，也不能作为改动依据。

## 4. 重要程度排序

取证、风险和验证按重要程度收敛：

1. 生产、数据、安全、不可逆操作。
2. 公共接口、隐性契约、返回值形态、异常行为、副作用顺序。
3. 跨模块调用、共享 schema、全局状态、配置和环境差异。
4. 用户可见行为、关键路径、核心验收。
5. 测试缺口、未验证路径、低置信推断。
6. 局部可读性、命名、风格和顺手优化。

规则：

- 先列会改变改法或验证策略的项。
- 同类问题只保留影响最大的一条。
- 最终收敛成 1-3 个用户拍板点或验证重点。

## 5. 通用取证

改动前围绕本次任务取证：

- 目标文件和目标函数。
- 调用方和被调用方。
- 相关测试。
- 共享数据结构、配置、全局状态或外部依赖。
- 最近相关变更记录、项目记忆层或用户口述雷区。

## 6. 稀有救火止损

只在生产、数据、安全或继续试错会扩大损害时启用。

先做：

- 保留现场：错误、日志、时间、输入、版本、最近变更、影响范围。
- 限制副作用：暂停批量任务、停止重复写入、避免继续重试。
- 先判断止血路径：回滚、降级、暂停入口、备份、只读取证。
- 未确认根因前，不做大重构、不清理现场、不顺手优化。

止损后再回到小改或 details。

## 7. 小改

重点是影响面和契约不变。

改前必须明确：

- 直接修改的文件 / 函数。
- 调用方和被调用方。
- 共享数据结构、全局状态或配置。
- 本次不应改变的行为：签名、返回值形态、副作用顺序、异常行为、性能特征。
- 验证路径：相关测试、最小复现或手动检查。

默认方案：

- 只做最小改动。
- 顺手优化单独列出，等待用户确认。
- 改后对照契约不变清单自查。
- 跑相关验证；跑不了时说明替代验证和剩余风险。
- 新发现的隐性契约、雷区、未验证项写入项目记忆层。

## 8. 读取 details

命中以下任一场景，读取 `flow_legacy_project.details.md`：

- 需要写或更新项目记忆层。
- 重构 / 大改。
- 加新功能涉及跨模块、新数据/状态/权限/外部依赖或新子系统。
- 涉及生产、数据、安全、迁移或不可逆操作。
- 影响面无法通过当前上下文收敛。
