# 专题索引: 执行流程

本专题处理任务怎么启动、怎么分阶段、什么时候接手、什么时候按新项目/老项目/救火路径走。

本文件只做执行流程路由。默认先判断任务路径，不自动读取所有流程文件。

## 触发入口

### 通用执行门禁

命中以下任一场景，读取 `workflow.index.md`:

- 准备改文件、运行会改变状态的命令、做验证或完成汇报。
- 中大任务、多阶段任务、多文件改动、用户纠偏或上下文压缩。
- 需要判断 Fast path / Normal path / Guarded path / Emergency path。

### 首次接手

命中以下任一场景，读取 `onboarding.index.md`:

- 首次接触项目或切换到陌生目录。
- 用户要求“接手 / 理解一下 / 先熟悉 / 看看项目”。
- 需要建立或更新项目地图、运行方式、核心目录职责。

### 新项目 / 新模块

命中以下任一场景，读取 `flow_new_project.index.md`:

- 从 0 到 1 建新项目、新模块、新工具或新架构地基。
- 需求边界不清，需要方案候选、取舍、拍板点。
- 用户说“设计一下 / 重新设计 / 怎么做更好”。

### 老项目改动

命中以下任一场景，读取 `flow_legacy_project.index.md`:

- 旧项目 bug 修复、小功能、局部重构。
- 需要沿用既有结构、控制影响面、避免误伤用户改动。
- 首次修改老项目代码但不是从 0 到 1 设计。

### 救火

命中以下任一场景，读取 `flow_emergency.index.md`:

- 生产事故、线上故障、严重 bug、数据损坏、安全风险。
- 用户明确说“救火 / 紧急 / 线上 / 生产 / 事故”。
- 继续试错可能扩大损害。

## 读取边界

- 小而明确的 Fast path 不因本索引存在而升级成完整流程。
- 命中多个流程时，优先级为: 救火 > 规则维护/高风险门禁 > 新项目/架构 > 老项目改动 > onboarding > workflow。
- 只读取能改变当前判断的流程文件；阶段切换后按闭包里的 `RULE_ROUTE` 或本索引重新判断。

## 维护重点

- 是否有清晰读取路径。
- 是否按任务规模区分轻量 / 标准 / 高风险路径。
- 是否避免把小任务拖进完整流程。
- 是否和 `workflow.index.md` 路由到的阶段切换、验证预算、停止条件重复定义。
