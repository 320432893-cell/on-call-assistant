本文件只做新项目 / 新模块路由。默认停在本文件，不自动读取 `flow_new_project.details.md`。

## 1. 轻量判断

默认先判断:

- 交付形态和用户真实验收路径。
- 是小项目、MVP、展示用途，还是中大型长期工程。
- 当前是讨论态、草案态还是用户已拍板执行。
- 是否走简单版流程，还是升级到标准流程。
- 哪些问题必须用户拍板，哪些可以先用假设推进。

## 2. 普通简单版

适用:

- 小项目、MVP、展示用途或短期工具。
- 用户只需要先跑通一版。

只输出:

1. 当前理解: 交付形态、验收动作、输入 / 处理 / 输出。
2. 业务理解复核: 先复述主业务逻辑，再补边缘、异常和极端场景。
3. 最低地基: source of truth、degraded / 回退、不做什么。
4. 关键风险: 先发散用户假设和同类项目常见问题，再收敛最多 3 条，按破坏等级排序。
5. 方案对照: 极简方案 vs 够用方案；需要时补一个更稳方案。
6. 推荐方向和 1-3 个用户拍板点。

## 3. 项目产物文件

新项目 / 新模块拍板后，检查是否需要维护：

- `docs/PROJECT_MAP.md`
- `docs/AI_HANDOFF.md`

处理：

- 用户未确认写入前，不创建或修改项目产物文件。
- 小项目只补最小产物，不写完整架构文档。
- 中大型项目、长期工程、新架构地基需要补或更新项目产物。
- 产物只记录已拍板事实、source of truth、degraded / 回退、未验证项和下次接手重点。

最小 `PROJECT_MAP.md` 只记录：

- 项目用途和不做什么。
- 交付形态和验收方式。
- 入口、运行方式、测试方式。
- 核心模块职责。
- Source of truth。
- Degraded / 回退。

最小 `AI_HANDOFF.md` 只记录：

- 当前任务目标、状态和用户已拍板内容。
- 未验证项。
- 下次接手先看哪里。

## 4. 读取 details

命中以下任一场景，读取 `flow_new_project.details.md`:

- 已判断为中大型项目、长期工程或新架构地基。
- 需要标准流程、阶段门、交付形态与业务画像。
- 需要假设与风险、架构候选、拍板前骨架。
- 需要展开项目产物的完整写入规则。
- 准备落盘中大型新项目、新模块、目录结构、工具链或架构地基。

小项目、MVP、展示用途或短期工具默认停在本索引的普通简单版，不读取 details。
