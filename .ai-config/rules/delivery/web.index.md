# Web 用户路径体检

本文件用于用户声明后的 Web 前端体检、审查、复盘和验收。体检目标是用二八法则找出最影响用户路径、数据可信度、接口兼容和前端安全边界的少数问题。

## 1. 二八体检顺序

按以下顺序检查：

1. 用户状态：loading、empty、error、success 是否和真实数据生命周期一致。
2. 接口映射：字段、状态码、错误结构、鉴权信息是否有明确映射位置。
3. 状态权威源：本地 state、store、URL、路由、后端、浏览器存储是否存在漂移。
4. 展示可信度：图表、表格、统计数字的字段、单位、时间范围、异常值是否清楚。
5. 安全边界：敏感字段、HTML / Markdown、token / cookie / storage、第三方脚本是否安全。
6. 验证路径：关键用户路径是否有组件测试、E2E、截图或定向手测证据。

## 2. 必查证据

| 体检项 | 必查证据 | 高风险信号 |
|---|---|---|
| 请求生命周期 | 请求、loading、empty、error、success、刷新 / 搜索 / 分页 | 旧响应覆盖新响应，失败留白 |
| 接口适配 | 字段映射、默认值、错误结构、兼容边界 | 后端字段漂移导致前端静默错显 |
| 状态权威源 | 状态来源、同步方向、冲突优先级 | URL、store、本地 state、后端互相覆盖 |
| 展示可信度 | 字段来源、单位、时间范围、统计口径、异常处理 | 图表数字不可追溯，单位和时间窗口不明 |
| 页面结构 | 页面职责、组件输入输出、表单校验边界 | 页面同时承担请求、转换、状态和大量展示 |
| 前端安全 | HTML / Markdown 渲染、下载文件名、浏览器存储、第三方脚本 | 敏感信息进控制台、storage 或未转义 HTML |

## 3. 高 ROI 体检项

| 体检项 | 合格判定 | 高风险信号 |
|---|---|---|
| 请求生命周期 | 每个关键请求有明确成功、空、失败、过期响应处理 | 加载永不结束、失败无反馈、重复提交 |
| 接口适配层 | 字段转换和兼容逻辑集中可查 | 字段兼容散在组件内 |
| 状态权威源 | 冲突时谁优先生效可说明 | 多处状态互相覆盖 |
| 展示可信度 | 统计口径、单位、时间范围可追溯 | 图表和表格无法解释 |
| 复杂异步 | 搜索、分页、筛选、轮询、取消、错误边界有策略 | 竞态、重复请求、过期响应污染 UI |
| Web 安全 | 敏感字段和注入入口有边界 | token、隐私数据、原始 HTML 暴露 |

## 4. ROI 判定

| 优先级 | 判定 | 推荐动作 |
|---|---|---|
| P0 | 用户主路径不可用、数据错显、敏感信息泄漏、接口错误静默 | 先修复或暂停验收 |
| P1 | 状态漂移、接口兼容风险、图表口径不清、关键路径未验证 | 补映射、补状态边界、补验证 |
| P2 | 非关键组件拆分、低风险样式和文案、局部体验优化 | 记录边界，低成本时处理 |

## 5. 输出闭包

Web 体检结论必须表格化，并包含：

- 最高风险的 1-3 个用户路径、数据可信度或安全问题。
- 证据位置：页面、组件、接口、字段、截图、测试或浏览器存储。
- 推荐处理：修复、补接口映射、补状态权威源、补验证或暂不处理。
- 未验证项：真实账号、真实数据、目标浏览器、后端错误分支、第三方脚本。
