# On-call 架构入口体检

本文件用于用户声明后的 On-call Assistant 架构体检、审查、复盘和验收。体检目标是用二八法则找出最影响长期入口承载、边界清晰度、故障隔离和可验证性的少数架构问题。

## 1. 二八体检顺序

按以下顺序检查：

1. 入口边界：Web、CLI、GUI、脚本入口是否承载过多业务流程。
2. 核心逻辑：核心处理是否依赖 UI / Web / CLI 框架对象，是否能独立测试。
3. 外部适配：HTTP、SDK、数据库、文件系统、消息队列是否穿透核心逻辑。
4. source of truth：配置、状态、缓存、外部服务结果和本地数据谁是权威源是否清楚。
5. 失败回退：超时、重试、降级、补偿、幂等和失败可见性是否明确。
6. 重复编排：多个入口是否重复编排同一业务流程，导致行为漂移。

## 2. 必查证据

| 体检项 | 必查证据 | 高风险信号 |
|---|---|---|
| 入口边界 | 入口文件、路由、命令、窗口启动代码 | 入口层包含大量业务分支和外部调用 |
| 核心逻辑 | 核心模块、函数签名、单元测试或可测试入口 | 业务逻辑依赖 request、response、widget、CLI args |
| 外部适配 | HTTP / SDK / DB / FS 调用位置 | 第三方细节直接进入核心逻辑 |
| 配置和 secret | 配置来源、环境变量、日志、文档 | URL、阈值、secret 散落在业务代码 |
| source of truth | 状态流向、缓存策略、冲突处理 | 多处都能改同一状态，冲突时无规则 |
| 失败回退 | 超时、重试、幂等、降级、补偿证据 | 无限重试、无超时、不幂等操作直接重试 |

## 3. 架构边界体检

| 层次 | 合格判定 | 失控信号 |
|---|---|---|
| 入口层 | 只做参数解析、配置加载、依赖装配、启动 | 入口层直接编排复杂业务、处理大量异常和回退 |
| 服务 / 编排层 | 组织流程，调用核心逻辑、仓储和适配器 | 多个入口各自复制流程 |
| 核心逻辑层 | 使用普通数据结构或明确模型，能脱离入口测试 | 依赖框架对象、全局状态或外部 IO |
| 外部适配层 | 封装 HTTP、SDK、DB、FS、消息队列 | 第三方响应结构向核心层泄漏 |

## 4. ROI 判定

| 优先级 | 判定 | 推荐动作 |
|---|---|---|
| P0 | 架构问题会导致主入口不可测、状态错乱、数据污染、失败不可恢复 | 先拆入口 / 核心 / 适配边界或补 source of truth |
| P1 | 多入口行为漂移、配置分散、外部依赖穿透、回退不可解释 | 局部解构或补边界文档和验证 |
| P2 | 复用不足、命名不齐、局部结构不够优雅 | 暂不处理，除非与 P0/P1 同路径 |

## 5. 输出闭包

架构体检结论必须表格化，并包含：

- 当前最影响长期承载的 1-3 个边界问题。
- 证据位置：入口、模块、调用链、配置、测试或运行日志。
- 推荐处理：先拆入口、先拆适配、补 source of truth、补验证或暂不处理。
- 不处理范围：避免把体检扩大成全量重构。
- 未验证项：真实入口、生产配置、外部服务、故障路径或部署方式。
