# 操作台 UI 体检

本文件用于用户声明后的桌面 GUI / 本地操作台体检、审查、复盘和验收。体检目标是用二八法则找出最影响任务状态可信度、UI 线程安全、错误恢复和诊断取证的少数问题。

## 1. 二八体检顺序

按以下顺序检查：

1. UI 线程：文件读写、网络请求、批处理、模型推理、导入导出是否阻塞 UI。
2. 任务状态：未开始、运行中、成功、失败、停止、部分成功是否和真实任务一致。
3. 生命周期：取消、停止、重试、关闭窗口、中间产物处理是否有明确路径。
4. UI 更新边界：后台任务是否只通过框架推荐机制回到 UI 线程更新界面。
5. 错误恢复：用户是否知道发生什么、影响什么、能做什么。
6. 诊断取证：最近错误、日志位置、任务状态、输入输出路径、版本和配置摘要是否可复制且脱敏。

## 2. 必查证据

| 体检项 | 必查证据 | 高风险信号 |
|---|---|---|
| UI 线程 | 耗时任务位置、线程 / worker / async 边界 | 主线程执行网络、文件、批处理或长计算 |
| UI 更新 | 信号、队列、回调、主线程调度方式 | 后台线程直接更新控件 |
| 任务状态 | 状态表、控件启停、非法状态处理 | UI 显示成功但后台失败，重复点击重复启动 |
| 生命周期 | 取消、停止、重试、关闭、中间产物处理 | 停止后状态不明，关闭窗口留下后台任务 |
| 错误恢复 | 用户提示、日志位置、恢复动作、脱敏 | 错误只有堆栈，用户不知道下一步 |
| 诊断取证 | 最近错误、日志、配置摘要、路径、版本、可复制文本 | 现场故障无法复现或定位 |

## 3. GUI 体检项

| 体检项 | 合格判定 | 高风险信号 |
|---|---|---|
| UI 状态机 | 控件启停和状态展示来自明确任务状态 | 多按钮互相影响但无状态表 |
| 线程 / 任务边界 | UI 线程只负责界面，后台负责耗时任务 | 后台任务和 UI 状态互相穿透 |
| 任务生命周期 | 运行、取消、停止、失败、部分成功、重试都有路径 | 失败和用户停止混在一起 |
| 错误恢复 | 用户提示和技术详情分层，敏感信息脱敏 | 直接弹内部异常或吞错 |
| 诊断取证 | 能复制诊断文本，能定位日志和输入输出 | 排障只能靠用户描述 |

## 4. ROI 判定

| 优先级 | 判定 | 推荐动作 |
|---|---|---|
| P0 | UI 卡死、重复启动、后台失败不可见、关闭后任务失控、敏感信息泄漏 | 先修复线程 / 状态 / 生命周期 / 取证 |
| P1 | 状态不可信、错误不可恢复、诊断不足、关键路径未验证 | 补状态表、补日志、补恢复动作或补验证 |
| P2 | 低风险控件布局、非关键文案、局部易用性增强 | 记录边界，低成本时处理 |

## 5. 输出闭包

操作台 UI 体检结论必须表格化，并包含：

- 最高风险的 1-3 个 UI 线程、任务状态、生命周期或诊断问题。
- 证据位置：窗口、控件、任务代码、日志、截图、手测或自动化结果。
- 推荐处理：修复、补状态表、补线程边界、补诊断、补验证或暂不处理。
- 未验证项：真实长任务、异常路径、目标系统、目标平台、关闭和取消路径。
