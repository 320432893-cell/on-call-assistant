# 数据体检

本文件用于数据读取、清洗、转换、过滤、写出的数据正确性和数据事故防护。重点防止静默丢数、重复写、复现不稳定、部分成功和覆盖人工数据；性能没有稳定模板，优先用日志记录耗时、定位慢点，再定点改。

## 1. 默认判断

按重要程度先看:

1. 是否会写出、覆盖、更新状态、删除、迁移或调用外部接口产生副作用。
2. 是否会过滤、修正、跳过、填充或终止数据处理。
3. 同一输入重复跑，结果是否稳定，是否会重复写或产生额外副作用。
4. 长任务失败后是否能恢复，是否会重复处理已完成数据。
5. 是否存在明显性能瓶颈，是否有耗时日志定位慢点。
6. 本次处理哪些结果已验证，哪些仍未验证。

很小的只读展示、单文件解析、临时转换，只需看真实样本、明确关键字段，不升级复杂规则。

## 2. 新数据源契约

第一次接入 Excel / CSV / JSON / 数据库表 / 接口返回，或数据结构可能变化时:

- 先读取真实样本，再写处理逻辑。
- 确认关键字段、类型、是否可空、实际样本值。
- 时间字段确认格式和时区。
- 金额 / 数值字段确认单位和精度。
- 文本字段跨系统时确认编码。

## 3. 请求 / 爬虫数据独立审查

请求、爬虫、批量下载或网页自动化抓取真实数据后，如果结果会进入写库、分析、报告、模型、业务判断或后续自动处理，除静态检查外，派独立子 agent 做数据质量审查。

临时探测、可丢弃样例、接口可用性试探、小规模手工确认不默认派子 agent；但发现空结果、字段变化、分页异常、权限/反爬提示或样本会被继续复用时，升级审查。

子 agent 审查重点:

- 空结果: 总量、关键分组、分页末页、过滤后结果是否异常为 0。
- 数据漂移: 字段新增/缺失/改名，类型变化，枚举变化，时间格式 / 时区变化，单位 / 精度变化。
- 合法性: 状态码、登录态、权限页、验证码/风控、反爬提示、限流、重定向、错误页是否被误当数据。
- 完整性: 分页、滚动加载、下载文件、批量循环是否漏页、重复页、截断或只拿到首屏。
- 代表性: 样本是否覆盖正常、空值、边界值、异常值和不同业务分类。
- 可复现: 请求参数、时间窗口、数据源版本、抓取时间、源 URL / query 是否可追溯。

审查结果用表格给用户拍板:

| 维度 | 结论 |
|---|---|
| 是否为空 | 总量、关键分组、过滤后数量 |
| 是否漂移 | 字段、类型、枚举、单位、时间格式变化 |
| 是否合法 | 是否命中登录/权限/限流/验证码/错误页 |
| 影响 | 会影响哪些写入、分析、报告或自动决策 |
| 建议 | 继续使用、补抓、修解析、人工确认或废弃本次数据 |

## 4. 脏数据处理

重点识别:

- 前后空格。
- 大小写混合。
- 不符合业务格式。
- 严重偏离期望值。
- 重复、缺失、非法枚举。

必须说明:

- 每类问题怎么处理: 保留、修正、跳过、终止、人工确认。
- 判断条件是什么，不能只写“清洗一下”。
- 被跳过、修正、填充的数据是否保留原值、原因和位置。
- 修正多少、跳过多少、人工确认多少。
- 默认值是否会改变业务含义；会改变时需要用户确认或标记未验证。

## 5. 清洗后归一化

清洗后再做归一化，不能把两步混在一起。

重点:

- 去空格。
- 统一大小写。
- 统一业务格式。
- 统一单位或编码。
- 给出至少一个清洗前后样本。

## 6. 重跑复现稳定

用于写文件、写数据库、更新状态、生成记录、调用外部接口产生副作用的任务。

- 明确重复执行场景: 手动重跑、崩溃重启、定时任务重叠、网络重试。
- 目标是同一输入重复跑，输出一致，不重复写、不多调用、不产生额外副作用。
- 可选做法: 唯一键、存在性检查、覆盖写、增量标记、事务、去重表、稳定文件名。
- 写入后说明如何证明重复执行结果稳定。

## 7. 长任务恢复

预计运行时间较长、数据量较大、中途失败重跑成本高、多阶段处理时:

- 明确检查点粒度: 记录数、阶段、时间间隔。
- 明确状态保存位置。
- 保存进度、已处理标识、处理上下文。
- 说明是否支持从检查点恢复；不支持时说明原因。
- 恢复逻辑不能重复写已完成数据。

## 8. 性能定位和定点优化

性能没有统一模板，先定位再改。

- 记录关键阶段耗时: 读取、清洗、转换、聚合、写出。
- 标出慢点，而不是先换引擎。
- 只对慢点定点优化。
- 常见优化方向: 批量写、减少循环内 IO、分块、索引、缓存、duckdb / polars。
- 新增重依赖前说明真实收益、执行代价和替代方案。
