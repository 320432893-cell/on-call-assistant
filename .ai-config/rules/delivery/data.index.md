# 数据交付体检

本文件用于用户声明后的数据体检、审查、复盘和验收。体检目标是用二八法则先找出最可能导致结果错误、数据破坏、不可复现或交付不可解释的少数问题。

## 1. 二八体检顺序

按以下顺序检查，命中高风险项时先处理高风险项：

1. 副作用：是否写文件、写库、覆盖、删除、迁移、更新状态或调用外部接口。
2. 正确性：过滤、修正、跳过、填充、聚合、金额、时间、单位是否改变业务含义。
3. 数据源契约：字段、类型、枚举、空值、时区、单位、编码是否已用真实样本确认。
4. 可复现：同一输入重复运行是否稳定，失败重跑是否会重复写或漏处理。
5. 完整性：分页、批量、下载、滚动加载、关联、去重是否漏页、重复、截断。
6. 性能定位：长任务是否有阶段耗时，慢点是否可定位。

## 2. 必查证据

| 体检项 | 必查证据 | 高风险信号 |
|---|---|---|
| 数据源契约 | 真实样本、字段清单、类型、空值、样例值 | 字段漂移、枚举变化、时间格式变化、单位不明 |
| 副作用 | 写入路径、表名、接口、覆盖策略、事务或检查点 | 覆盖已有文件、重复写库、外部接口不可回滚 |
| 脏数据 | 问题类型、判断条件、处理数量、保留原值位置 | 默认值改变业务含义、跳过数据无记录 |
| 聚合计算 | 分组键、金额单位、精度、时间窗口、去重口径 | 金额翻倍、时区错位、重复记录参与统计 |
| 重跑恢复 | 唯一键、存在性检查、稳定文件名、进度记录 | 崩溃后只能从头跑、重复执行产生额外副作用 |
| 性能 | 读取、清洗、转换、聚合、写出耗时 | 未定位慢点就换引擎或加重依赖 |

## 3. 请求 / 爬虫数据体检

请求、爬虫、批量下载或浏览器自动化抓取的数据会进入写库、分析、报告、模型、业务判断或后续自动处理时，必须增加独立数据质量体检。

体检表必须覆盖：

| 维度 | 判定内容 |
|---|---|
| 是否为空 | 总量、关键分组、过滤后数量是否异常 |
| 是否漂移 | 字段、类型、枚举、单位、时间格式是否变化 |
| 是否合法 | 登录页、权限页、验证码、限流、错误页是否被误当数据 |
| 是否完整 | 分页、滚动、下载、循环是否漏页、重复或截断 |
| 是否可复现 | 请求参数、时间窗口、数据源版本、抓取时间、源 URL / query 是否可追溯 |

## 4. ROI 判定

| 优先级 | 判定 | 推荐动作 |
|---|---|---|
| P0 | 会破坏数据、覆盖不可恢复、报告结论可能反向、权限页被当数据 | 先停下补证据或改处理逻辑 |
| P1 | 会影响主要统计、关键分组、验收口径、失败重跑 | 补样本、补记录、补验证或局部修复 |
| P2 | 只影响边缘样式、非关键字段、一次性人工可确认结果 | 记录边界，低成本时处理 |

## 5. 输出闭包

数据体检结论必须表格化，并包含：

- 最高风险的 1-3 个问题。
- 证据位置：样本、字段、代码、输出文件、数据库表、日志或测试结果。
- 推荐处理：继续使用、补抓、修解析、人工确认、废弃本次数据或暂不处理。
- 未验证项：无法读取的外部系统、业务口径、权限页面或真实环境。
