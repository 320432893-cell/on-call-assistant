# 用户交互体检

本文件用于用户可见交互的默认判断，不绑定 GUI、Web、CLI 或具体框架。重点是让用户知道能做什么、发生了什么、失败后怎么办，以及问题能否被取证。

## 1. 默认判断

按重要程度先看:

1. 用户目标是否可见: 当前能做什么、下一步是什么、当前处于什么状态。
2. 动作是否可控: 耗时任务有反馈，可中止任务有停止 / 取消入口，重复点击有防护。
3. 后果是否可预期: 删除、覆盖、清空、重置、批量操作、终止任务要说明对象、影响范围、是否可逆。
4. 失败是否可恢复: 用户知道原因、影响范围和下一步能做什么。
5. 信息是否可取证: 错误、日志、路径、任务 ID、配置摘要、版本信息尽量可复制且脱敏。
6. 界面是否可承载: 长文本、长路径、日志、表格、大结果集不能撑爆界面。
7. 本次验证覆盖了哪些用户路径，哪些仍未验证。

纯后端、小数据处理、小路径 bug、无用户可见变化时，不读取本文件。

## 2. 按钮四态

用户触发的主要按钮至少考虑四种状态:

- 默认态: 按钮文案说明动作，不用抽象名词；一个界面尽量只有一个最突出的主操作。
- 运行态: 点击后立即进入运行反馈，耗时动作禁用重复触发；可中止任务显示停止 / 取消入口。
- 成功态: 明确告诉用户结果在哪里、是否已保存、下一步能做什么。
- 失败态: 用业务语言说明发生了什么、影响什么、用户能做什么；技术详情进入日志或诊断信息。

危险按钮:

- 删除、覆盖、清空、重置、批量操作等危险动作要区分视觉层级。
- 确认框说明对象和影响范围。
- 默认焦点优先在取消或安全选项。
- 危险动作不应被 Enter、双击、重复点击轻易误触发。

## 3. 窗口和内容承载

- 错误、日志、结果、路径、诊断文本、任务 ID、输出摘要默认应可复制。
- 主窗口、主工作区、日志区、结果区、表格 / 列表区默认应可拉伸或可调节大小。
- 内容超过容器时必须能滚动；界面太长要有上下滚动，表格太宽或长路径太宽要有左右滚动。
- 表格列多、文本长、数据量大时，考虑横向滚动、换行、截断 + 展开、虚拟滚动或分页。
- 复制失败、复制空内容、复制不可见截断内容都算交互缺陷。
- 空状态、无匹配、无权限、加载失败不能留白。
- 短表单、确认框、简单设置框可以固定尺寸，但文本不能被截断到不可理解。

## 4. 文件和路径输入

- 文件路径入口要多样: 按钮选择、粘贴路径、手动输入、最近路径、拖拽按实际场景组合，不把用户卡死在一种输入方式里。
- 单文件输入、文件夹输入、多文件输入要明确区分，不用一个按钮含糊表示。
- 选择文件后显示完整路径或可复制路径；路径太长时可截断显示，但复制必须拿到完整路径。
- 允许重新选择、清空选择；无效路径、格式不支持、权限不足时给出明确提示。
- 适合拖拽的场景: 单文件导入、批量文件导入、文件夹批处理、本地工具快速投喂。
- 如果顺序会影响结果，要提供排序、上移下移或导入后预览，不只靠拖拽顺序。
- 如果不同输入位置有不同含义，要用明确槽位、标签或分区，不只给一个混合拖拽区。
- 如果涉及远程路径、权限说明、覆盖已有文件或批量写出，要提供可复制路径、影响范围和确认步骤，拖拽只能作为增强入口。
- 拖拽不能替代按钮选择、粘贴路径或手动输入。
- 文件夹输入要说明是否递归、支持哪些后缀、输出写到哪里。

## 5. 任务和关闭行为

- 运行中任务要显示阶段、进度、日志流三者之一；复杂任务优先日志或阶段。
- 用户主动停止和系统失败必须区分。
- 停止后说明中间产物如何处理: 清理、保留、标记部分完成或等待用户决定。
- 关闭窗口只在运行中任务、未保存修改、未完成输出或不可恢复状态时确认。
- 简单关闭不弹确认，避免打扰。

## 6. 诊断取证

复杂 GUI、内部工具、批处理工具、文件处理工具、有后台任务的工具，应有诊断入口或等价取证方式。

最低可用诊断信息:

- 当前任务状态。
- 最近错误。
- 日志路径。
- 当前配置摘要。
- 输入 / 输出路径。
- 版本信息。
- 可复制诊断文本。

安全边界:

- 不展示密钥、token、密码、完整隐私数据。
- 配置摘要应脱敏。
- 诊断入口不能成为普通用户绕过权限或读取敏感信息的入口。
- Web 不默认劫持浏览器 F12；桌面 GUI 可优先考虑 F12 打开 / 关闭诊断面板。

## 7. 成本匹配和习惯

- 小工具不强制完整调试中心；复杂批处理、文件处理、内部工具必须考虑诊断入口。
- 遵守平台、浏览器、框架和项目已有习惯，不发明反直觉交互。
- `Ctrl+C` 复制、`Esc` 关闭弹窗、`Enter` 提交要按场景谨慎使用；危险操作不应被误触发。
- 用户明确要求的交互如果会制造误操作、误删、卡死、排查困难或维护负担，应说明风险并给更稳的替代方案。

## 8. 验证记录

- 交互改动完成后，说明验证过哪些用户路径。
- 涉及按钮四态、危险操作、文件/文件夹选择、拖拽、关闭行为、诊断入口、窗口承载、复制、滚动时，优先截图、手测或 E2E 验证。
- 无法验证时写入 taskwork 阶段总结的“未验证”，说明原因和剩余风险。
