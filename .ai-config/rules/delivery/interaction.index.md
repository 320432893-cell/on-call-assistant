# 用户交互规则索引

本文件只做交互规则路由。默认停在本文件，不自动读取 `interaction.details.md`。

## 1. 不继续读取

命中以下场景时，不读取交互细节:

- 纯后端逻辑、小数据处理、小路径 bug。
- 不改变用户可见界面、提示、按钮、窗口、命令输出。
- 用户明确只要内部实现修复。

## 2. 轻量交互判断

命中以下场景时，只用本文件做轻量判断，必要时读取 `interaction.details.md` 的对应章节:

- 新建或修改按钮、表单、弹窗、菜单、快捷键、窗口、结果区、日志区。
- 新增错误提示、空状态、加载状态、成功 / 失败反馈。
- 新增关闭、取消、停止、重试、导出、复制等用户动作。
- 用户提到交互、体验、好用、按钮、窗口、弹窗、F12、调试入口。

动作:

- 先判断用户目标、误操作风险、失败恢复和验证方式。
- 小改只做必要交互判断，不把任务升级成完整 UX 设计。
- 只有下面复杂条件命中时，才读取 `interaction.details.md`。

## 3. 读取 details

命中以下任一场景，读取 `interaction.details.md`:

- 复杂 GUI、本地工具、内部工具、批处理工具、文件处理工具。
- 有后台任务、长时间运行、日志输出、文件输入输出、用户协作排障。
- 有危险操作、不可逆操作、未保存状态、运行中关闭。
- 需要 F12 或等价诊断入口、诊断信息脱敏、用户协作取证。
- 复杂交互需要用户拍板，或用户要求可能制造误操作、误删、卡死、排查困难、维护负担。

读取边界:

- 不因为 `interaction.details.md` 存在就默认读取。
- 读取 details 后，仍只使用当前任务命中的章节。
- details 里的示例库只用于激活联想，不当作穷尽清单。

## 4. 下一步规则路由

- 涉及 Web 前端组件、API、状态、图表或安全时，优先回到 `../engineering/frontend.index.md`；若已由 frontend 路由进入，本文件只处理交互章节，除非发现新的 API、状态、图表或安全风险。
- 涉及桌面 GUI 线程、后台任务、状态生命周期时，优先回到 `../engineering/gui.md`；若已由 gui 路由进入，本文件只处理用户动作、诊断入口、误操作和反馈文案。
- 涉及打包、分发、正式交付时，读取 `package.index.md`。
- 涉及数据写出、覆盖、合并、对账时，读取 `data.index.md`。
