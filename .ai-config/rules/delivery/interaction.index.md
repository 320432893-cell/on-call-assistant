# 用户交互交付体检

本文件用于用户声明后的交互体检、审查、复盘和验收。体检目标是用二八法则先检查最影响用户完成任务、理解后果、恢复失败和提供取证的交互问题。

## 1. 二八体检顺序

按以下顺序检查：

1. 用户目标是否可见：当前能做什么、正在发生什么、下一步是什么。
2. 动作是否可控：耗时任务有反馈，重复点击有防护，可中止任务有停止 / 取消入口。
3. 后果是否可预期：删除、覆盖、清空、重置、批量、终止任务说明对象、范围、是否可逆。
4. 失败是否可恢复：错误提示说明原因、影响范围、用户下一步动作。
5. 信息是否可取证：错误、日志、路径、任务 ID、配置摘要、版本信息可复制且脱敏。
6. 界面是否可承载：长文本、长路径、日志、表格、大结果集不遮挡、不截断到不可理解。

## 2. 必查证据

| 体检项 | 必查证据 | 高风险信号 |
|---|---|---|
| 按钮四态 | 默认、运行、成功、失败状态截图或路径 | 点击后无反馈、可重复触发、失败无下一步 |
| 危险动作 | 确认框文案、默认焦点、对象和影响范围 | Enter / 双击 / 重复点击可误删或覆盖 |
| 任务状态 | 阶段、进度、日志、停止、失败、部分成功 | UI 显示成功但后台失败，停止和失败混淆 |
| 窗口承载 | 滚动、复制、拉伸、长路径、表格宽度 | 内容被截断、复制不到完整信息 |
| 文件路径 | 选择、粘贴、重选、清空、权限错误 | 只能靠一种入口，路径错误无法恢复 |
| 诊断取证 | 最近错误、日志位置、配置摘要、版本、可复制文本 | 出错后只能让用户截图或复述 |

## 3. 交互体检清单

### 按钮和危险动作

- 主操作按钮必须让用户看懂动作结果。
- 耗时动作必须进入运行态，并防止重复触发。
- 成功态必须说明结果位置、保存状态和下一步。
- 失败态必须说明发生什么、影响什么、用户能做什么。
- 危险动作必须说明对象、范围、是否可逆，并使用安全默认焦点。

### 窗口和内容承载

- 日志、错误、路径、结果、任务 ID、诊断文本必须可复制。
- 长内容必须支持滚动、截断展开或完整复制。
- 表格、日志区、结果区必须能承载真实数据量。
- 空状态、无权限、无匹配、加载失败不能留白。

### 文件和路径输入

- 单文件、文件夹、多文件输入必须区分清楚。
- 路径过长可以截断展示，但复制必须得到完整路径。
- 无效路径、格式不支持、权限不足必须给出恢复动作。
- 顺序影响结果时必须提供排序、预览或明确顺序规则。

### 任务和关闭行为

- 运行中任务必须能看出阶段、进度或日志。
- 用户停止、系统失败、部分成功必须在 UI 和日志中区分。
- 停止后必须说明中间产物处理方式。
- 关闭窗口只在运行中任务、未保存修改、未完成输出或不可恢复状态时确认。

## 4. ROI 判定

| 优先级 | 判定 | 推荐动作 |
|---|---|---|
| P0 | 可能误删、误覆盖、重复提交、任务卡死、失败不可恢复 | 先修或补强确认 / 状态 / 取证 |
| P1 | 影响主路径完成、错误理解、验收体验、排障效率 | 局部修复或补验证 |
| P2 | 不阻塞主路径的文案、布局、快捷入口优化 | 记录边界，低成本时处理 |

## 5. 输出闭包

交互体检结论必须表格化，并包含：

- 最高风险的 1-3 个用户路径问题。
- 证据位置：页面、窗口、控件、截图、日志、测试或手测结果。
- 推荐处理：修复、补验证、保持现状或暂不处理。
- 未验证项：真实用户路径、权限状态、长任务、异常场景或目标环境。
