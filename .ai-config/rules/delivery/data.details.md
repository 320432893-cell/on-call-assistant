# 数据风险门禁

## 1. 文件定位

触发:

- 读取、清洗、合并、转换、过滤、写出数据。
- 接入新 Excel / CSV / JSON / 数据库表 / 接口返回。
- 修改数据写入逻辑。
- 处理脏数据、重复数据、缺失值、格式不一致。

动作:

- 本文件只管数据正确性和数据事故防护。
- 重点防止静默丢数、错关联、重复写、部分成功、覆盖人工数据。
- 不向上引用其他规则，避免读取链路膨胀。

边界:

- 普通代码异常、日志、接口设计由代码语义规则处理。
- 数据任务很小且只读展示时，走轻量门禁；涉及写入、合并、过滤、金额、生产数据时升档。

## 2. 执行分级

轻量任务:

- 只读展示。
- 单文件解析。
- 不写回、不合并、不过滤关键数据。

必须做:

- 读取真实样本。
- 明确关键字段。
- 说明明显脏数据如何处理。

高风险任务:

- 多文件合并 / 比对。
- 过滤、去重、汇总、金额计算。
- 写文件 / 写数据库 / 更新状态。
- 覆盖已有 Excel / CSV / JSON。
- 长时间或大批量处理。

必须做:

- 数据契约。
- 归一化策略。
- 幂等策略。
- 对账指标。
- 失败处理。

反向审查:

- 数据任务太轻会静默出错。
- 数据任务太重会让小脚本被表格拖死。
- 判定重点不是文件格式，而是是否会改变、丢弃、合并、写出业务数据。

## 3. 新数据源契约

触发:

- 第一次接入数据源。
- 数据源结构可能变化。
- 用户只口述字段，AI 没看真实样本。

动作:

- 先读取真实样本，再写处理逻辑。
- 至少确认关键字段、类型、是否可空、实际样本值。
- 时间字段必须确认格式和时区。
- 金额 / 数值字段必须确认单位和精度。
- 文本字段涉及跨系统时确认编码。

阻断:

- 未看真实样本就写解析逻辑。
- 关键字段没有实际样本值。
- 时间、金额、单位靠猜。

## 4. 关联键与归一化

触发:

- 合并、比对、join、去重、关联。

动作:

- 明确关联键。
- 说明关联键归一化策略: strip、大小写、格式、单位、编码。
- 给出至少一个归一化前后样本。
- 明确缺失值策略: 填充、标记、丢弃、终止。

阻断:

- 多源合并未声明关联键。
- 关联键归一化靠默认猜测。
- 缺失值处理未定义。
- 去重依据不清。

## 5. 脏数据策略

触发:

- 用户输入。
- 外部文件。
- 爬虫结果。
- 第三方接口。
- 历史数据。

动作:

- 识别主要脏数据类型: 空值、类型不匹配、格式错误、重复、越界、非法枚举。
- 明确处理策略: 跳过并记录、默认值、修正、终止、人工确认。
- 对被丢弃或修正的数据保留可追溯记录。
- 高风险数据输出清洗统计。

阻断:

- 遇到脏数据静默跳过。
- 默认值会改变业务含义却未说明。
- 清洗后无法知道丢了多少、改了多少。

## 6. 幂等写入

触发:

- 生成记录。
- 写文件。
- 写数据库。
- 更新状态。
- 调用外部接口产生副作用。

动作:

- 明确重复执行场景: 手动重跑、崩溃重启、定时任务重叠、网络重试。
- 至少采用一种幂等策略: 唯一键、存在性检查、覆盖写、增量标记、事务、去重表。
- 写入后能证明重复执行不会产生重复数据或额外副作用。

阻断:

- 数据写入没有幂等策略。
- 重试会重复写且无去重键。
- 生成文件名不稳定导致重复产物无法识别。

## 7. 长任务检查点

触发:

- 预计运行时间较长。
- 数据量较大。
- 中途失败重跑成本高。
- 多阶段处理。

动作:

- 明确检查点粒度: 按记录数、阶段、时间间隔。
- 明确状态保存位置。
- 保存进度、已处理标识、处理上下文。
- 说明是否支持从检查点恢复；不支持时说明原因。

阻断:

- 长任务无检查点，失败只能从头重跑。
- 有检查点但无法判断哪些数据已处理。
- 恢复逻辑可能重复写。

## 8. 覆盖与人工修改冲突

触发:

- 覆盖、追加、修改已有 Excel / CSV / JSON / 数据文件。
- 写入用户可能手工编辑过的文件。

动作:

- 写入前确认目标文件是否存在。
- 覆盖写必须备份。
- 追加或修改必须说明冲突检测方式: 时间戳、hash、版本号、人工确认。
- 写入产物应带版本、时间或批次标识。

阻断:

- 覆盖已有文件无备份。
- 可能有人手工改过却不检查冲突。
- 写入区域不清楚。

## 9. 完整性对账

触发:

- 合并、转换、过滤、去重、聚合、写出后。

动作:

- 对比处理前后指标。
- 至少选择与任务相关的指标: 行数、关键字段去重数、金额/数量总和、错误数、输出文件数。
- 差异必须能解释。
- 无法解释时停止继续写出或标记为未验证。

阻断:

- 过滤或合并后没有前后指标。
- 行数差异无法解释。
- 金额 / 数量总和差异无法解释。
- 对账失败仍继续覆盖正式结果。

## 10. 多步写入失败模式

触发:

- 两步以上 IO / DB / 外部调用。
- 状态变更链。
- 文件和数据库同时写。

动作:

- 明确原子性边界。
- 每一步失败都要有处理策略: 回滚、补偿、标记重试、告警人工。
- 每个失败点要能通过日志、状态码、检查点定位。
- 重试必须幂等。

阻断:

- 多步写入未声明哪些步骤必须一起成败。
- 中间步骤失败无补偿或标记。
- 部分成功后系统看起来像全部成功。

## 11. 引擎与性能偏好

触发:

- 大数据量。
- 明显性能瓶颈。
- 需要反复查询或聚合。

默认:

- 小数据优先简单可靠。
- 大数据优先流式、分块、索引、duckdb / polars 等合适工具。
- 避免循环内逐行写入，优先批量写。

边界:

- 不为小数据引入复杂引擎。
- 新增重依赖前必须说明收益和替代方案，由用户决定。

## 12. 本文件反模式

- 没看真实样本就写解析。
- join 前不定义关联键。
- 处理后不对账。
- 覆盖文件不备份。
- 重跑会重复写。
- 脏数据静默丢弃。
- 部分成功被包装成全部成功。
- 小脚本套完整数据治理表格。
