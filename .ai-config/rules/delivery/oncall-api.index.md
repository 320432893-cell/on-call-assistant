# On-call API 契约体检

本文件用于用户声明后的 On-call Assistant HTTP API 体检、审查、复盘和验收。体检目标是用二八法则找出最可能导致调用方破坏、权限漏判、事务半成功、后台任务不可见和错误响应泄漏的少数问题。

## 1. 二八体检顺序

按以下顺序检查：

1. 契约兼容：路径、方法、参数、响应字段、状态码、错误结构是否改变调用方行为。
2. 权限边界：公开、登录用户、管理员、内部调用、服务间调用是否清楚。
3. 资源所有权：用户、租户、项目、设备、文件等资源是否校验访问范围。
4. 写入事务：多步写入、schema、迁移、回滚、批量更新是否存在半成功风险。
5. 异步任务：后台任务、长任务、调度器、队列、async 边界是否有失败可见性。
6. 可观测性：5xx、慢请求、trace_id、请求日志、错误日志和错误响应是否可定位且不泄漏。

## 2. 必查证据

| 体检项 | 必查证据 | 高风险信号 |
|---|---|---|
| API 契约 | 路由、请求模型、响应模型、状态码、错误结构 | 破坏旧字段、错误结构暗改、直接返回内部对象 |
| 权限身份 | 依赖注入、中间件、用户身份传递、角色判断 | 新路由权限不明，临时接口暴露后果不清 |
| 资源边界 | owner / tenant / project / file 校验位置 | 只验证登录，不验证资源归属 |
| 事务写入 | session / transaction、commit 顺序、补偿策略 | 多层各自 commit，事务内有外部 HTTP 或长 IO |
| 后台任务 | 任务生命周期、异常日志、重试、持久化、关闭策略 | `create_task` 静默失败，请求级 session 被后台复用 |
| 错误响应 | 5xx、业务错误、日志、trace_id、脱敏 | 堆栈、SQL、路径、密钥、第三方响应泄漏 |

## 3. API 契约体检

- 路径、HTTP 方法、请求参数、响应字段、状态码、错误结构都按契约检查。
- 公开接口和内部接口都必须说明调用方、暴露边界和鉴权方式。
- 破坏性变更必须列出影响的前端、外部调用方或内部服务。
- 直接返回 ORM 对象、内部配置对象、异常对象、未过滤第三方响应判为高风险。

## 4. 异步和后台任务体检

| 场景 | 合格判定 | 高风险信号 |
|---|---|---|
| `BackgroundTasks` | 短任务、失败可接受、可人工重试 | 重要任务、长任务、需要重试或监控 |
| 队列 / 调度器 | 有持久化、重试、监控、失败清单 | 失败用户不可见，无法追踪任务结果 |
| `asyncio.create_task` | 有异常可见性、关闭策略、资源隔离 | 脱离请求生命周期后静默失败 |
| async 路由阻塞 IO | 有线程池、异步客户端或明确隔离 | 同步 HTTP、文件 IO、sleep 阻塞事件循环 |

## 5. ROI 判定

| 优先级 | 判定 | 推荐动作 |
|---|---|---|
| P0 | 权限泄漏、数据半成功、契约破坏、错误泄密、后台任务静默失败 | 先修复或暂停发布 |
| P1 | 调用方兼容风险、错误不可定位、事务边界不清、验证不足 | 补契约、补鉴权、补事务说明或补验证 |
| P2 | 命名一致性、低风险字段扩展、非关键日志增强 | 记录边界，低成本时处理 |

## 6. 输出闭包

API 体检结论必须表格化，并包含：

- 最高风险的 1-3 个 API 契约或运行问题。
- 证据位置：路由、模型、调用方、日志、测试、数据库写入结果。
- 推荐处理：修复、补兼容、补鉴权、补事务、补观测或暂不处理。
- 未验证项：真实调用方、权限账号、数据库状态、后台任务结果、生产日志。
