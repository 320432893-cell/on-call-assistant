# 浏览器自动化交付体检

本文件用于用户声明后的 Playwright / Selenium / RPA / 浏览器脚本体检、审查、复盘和验收。体检目标是用二八法则先确认登录能接上、状态能识别、失败能取证、批量能恢复、副作用不会误执行。

## 1. 二八体检顺序

按以下顺序检查：

1. 业务闭环：动作、成功信号、失败信号、中止边界是否清楚。
2. 登录和授权：登录态、验证码、短信、滑块、人机验证、权限页是否被正确处理。
3. 等待和定位：locator、等待条件、iframe、新 tab、弹窗、下载上传是否稳定。
4. 副作用安全：提交、审批、删除、批量写入、重复执行是否会造成误操作。
5. 失败取证：失败时是否自动保存 URL、截图、日志、HTML、console、network 证据。
6. 批量恢复：进度、检查点、失败清单、重试边界是否可验证。

## 2. 必查证据

| 体检项 | 必查证据 | 高风险信号 |
|---|---|---|
| 业务闭环 | 动作清单、成功信号、失败信号、中止条件 | 未识别状态仍继续提交或抓取 |
| 登录授权 | 登录态检测、人工验证流程、cookie / storage state 保护 | 验证码被当普通异常，凭据进入日志 |
| 等待定位 | locator 策略、等待条件、iframe / popup / download 处理 | 固定 sleep、动态 class、复用旧句柄 |
| 副作用安全 | 幂等策略、重复执行影响、回滚或暂停点 | 重复提交、重复审批、重复下载覆盖 |
| 失败取证 | 截图、URL、标题、HTML、console、失败请求、时间戳 | 失败后只剩异常文本 |
| 批量恢复 | 当前页 / 记录、成功失败数、失败清单、检查点 | 失败后只能从头重跑或静默漏项 |

## 3. 用户-AI 协作边界

| 场景 | 体检判定 |
|---|---|
| 验证码 / 短信 / 滑块 / 人机验证 | 视为访问控制或风控信号，默认人工介入，不绕过 |
| 第三方打码 / 反检测 / 绕过策略 | 必须先确认授权、合规和目标系统规则 |
| 目标系统是否允许自动化不确定 | 标记为未确认，先让用户确认 |
| F12 取证 | 最多 3 步，说明面板、操作、回传内容和用途 |
| 诊断性 JS 注入 | 只用于读取 DOM 状态、验证事件链或定位问题，不绕过权限和业务校验 |

## 4. Playwright 体检重点

- 优先检查语义 locator、role/text/label/稳定属性和自动等待。
- 关键元素必须等待明确状态：visible、attached、enabled、detached、URL 或 network。
- 新 tab / 弹窗用 popup/page 事件，下载用 download 事件，dialog 在触发前准备处理。
- iframe 必须显式定位 frame，跨 frame 后重新定位元素。
- 复杂失败必须优先保存 trace、截图、HTML、console、network 证据。
- 原生 Playwright 能表达的等待、定位、上传、下载、弹窗处理，不用 JS 注入替代。

## 5. ROI 判定

| 优先级 | 判定 | 推荐动作 |
|---|---|---|
| P0 | 会误提交、误删除、绕过权限、泄露凭据、批量丢数据、失败不可恢复 | 先暂停并补状态识别、授权确认或取证 |
| P1 | 会导致登录不稳、定位脆弱、批量重跑成本高、验收不可复现 | 补等待、失败清单、检查点或关键路径验证 |
| P2 | 非关键选择器优化、日志格式、低风险取证增强 | 记录边界，低成本时处理 |

## 6. 输出闭包

浏览器自动化体检结论必须表格化，并包含：

- 最高风险的 1-3 个自动化问题。
- 证据位置：脚本、页面 URL、截图、trace、日志、失败清单、目标系统状态。
- 推荐处理：修复、补授权确认、补取证、补检查点、暂停执行或暂不处理。
- 未验证项：账号权限、验证码、真实目标系统、批量数据、网络环境、目标系统规则。
