# 打包与交付规则

本文件管构建产物、打包、分发、版本、配置、运行时依赖和交付验证。目标是交付物在目标环境能跑、能配置、能追溯、能排查，不靠开发机残留依赖侥幸成功。

命中打包、构建产物、exe、zip、Docker、Web 服务、CLI、HTML 展示页、演示稿、非开发机运行、他人使用时读取本文件。

## 1. 先判断交付级别

轻量试包: 本机临时试包、给自己验证打包命令。

- 可以复用开发环境。
- 至少运行一次产物或等价入口。
- 必须说明这不是正式交付验证。
- 不把“本机能跑”当成正式交付完成。

正式交付: 发给其他用户、部署测试 / 生产、客户现场、需要用户按说明安装配置运行。

- 检查依赖、资源、配置、版本、运行时外部依赖。
- 跑最小可用链路。
- 给出分发清单、用户说明、验证结果、未验证项和剩余风险。

高风险交付: 多环境、生产配置、密钥、账号、证书、自动更新、安装器、服务注册、系统权限、计划任务、数据迁移、覆盖用户文件、不可逆副作用。

- 先讨论环境、回滚、密钥、权限、验收路径和失败处理。
- 用户明确拍板后再做。

## 2. 依赖、资源和动态加载

- 先识别项目实际依赖来源: `pyproject.toml`、lock 文件、requirements、package manager、子项目依赖。
- Python 包安装需要联网时，默认优先清华源。
- 动态加载要额外检查: `importlib`、`spec_from_file_location`、`__import__`、`sys.path` 修改、插件目录。
- 静态资源要明确是否随产物分发: 模板、图片、图标、配置样例、证书占位、浏览器驱动、Playwright browsers、模型文件。
- 运行时生成内容不要预打进产物: 日志、缓存、临时文件、输出目录里的旧结果。
- PyInstaller 目录版默认整体分发 `dist/<name>/`，不能只拿 exe。
- 发现依赖缺失时，优先修构建配置或依赖声明，不靠用户手动复制 site-packages。

## 3. 构建环境和复现

- 正式交付应使用干净或专用构建环境，避免开发机残留依赖污染。
- 构建命令、依赖安装方式、目标平台、Python/Node 版本应可复现。
- 不擅自切换包管理器或构建工具；先识别项目现有工具链。
- 构建脚本尽量自动生成版本、收集资源、清理旧产物和执行 smoke test。
- 临时手工步骤越多，下一次交付越容易失败；必须写进交付说明或脚本。

## 4. 配置、密钥和运行时目录

- 产物不得内置生产密钥、账号、token、证书私钥或不可公开 URL。
- 环境差异通过配置文件、环境变量、启动参数或部署配置表达，不通过改代码重打包。
- 需用户修改的配置必须说明字段、示例、必填 / 可选、默认值和错误提示位置。
- 运行时目录必须明确: 日志、输出、缓存、下载、临时文件、配置文件。
- 多环境交付要明确 dev/test/prod 的配置来源、密钥隔离和切换方式。
- 配置样例可以随产物分发，真实密钥不能随产物分发。

## 5. 版本和构建元数据

- 正式交付产物必须能追溯来源: 版本号、git commit、构建时间、构建环境。
- 运行时应能查看版本信息: `--version`、`/version`、`/health`、GUI 关于页、标题栏、VERSION 文件等任选适合方式。
- 临时试包可以轻量标记，但不能和正式版本混淆。
- 版本号不要只靠手写常量；优先由 git tag、commit、构建时间或构建脚本生成。

## 6. 最小可用链路验证

正式交付前必须跑最小可用链路，按交付形态选择:

- 桌面程序: 主窗口可打开，核心操作可执行，资源加载正常，退出流程正常。
- CLI: `--help` 可用，核心命令可跑，错误退出码合理，输出路径可写。
- Web 服务: 根路径或健康检查可访问，关键 API 正常，静态资源正常，配置加载正确。
- HTML 展示页 / 演示稿: 入口可打开，核心页面或翻页路径可浏览，图片、字体、图表等静态资源可加载；投屏或打印要说明验收方式。
- 浏览器自动化工具: 浏览器可启动，登录 / 人工登录流程明确，关键页面可达，下载 / 输出路径可写。
- Docker / 服务部署: 容器可启动，health check 可过，日志可查看，配置挂载路径正确。

验证失败时，不得视为交付完成；必须说明失败点、修复方案或未验证风险。

## 7. 分发清单和用户说明

正式分发必须说明:

- 分发内容: exe 目录、zip、Docker 镜像、脚本包、配置样例、资源目录。
- 启动方式: 双击、命令行、服务启动、Docker 命令、计划任务。
- 外部运行时依赖: 浏览器、Playwright browsers、数据库客户端、VC++ 运行库、系统权限、网络访问。
- 用户需要修改的配置: 文件位置、字段含义、示例、必填项。
- 日志位置、输出位置、缓存位置、临时文件位置。
- 常见失败和排查方式。
- 升级或覆盖安装时，哪些文件应保留，哪些可以删除。

PyInstaller 目录版要明确:

- `exe` 与 `_internal` 或依赖目录必须保持相对位置。
- 不要单独分发 exe。
- 用户说明中写清“整个目录一起复制 / 解压后运行”。

## 8. 体积、运行时依赖和现场排障

- 正式交付记录产物大小；体积明显异常时再深入排查。
- 体积异常常见原因: 环境污染、误收集可选依赖、浏览器 / 模型 / 大数据文件、hook 误收集、动态导入扩大依赖。
- 运行时外部依赖必须列清楚，尤其是浏览器、Playwright browsers、驱动、VC++ 运行库、字体、系统库、数据库客户端。
- 打包失败优先排查入口、依赖声明、资源收集、spec / 构建配置，不顺手重构业务代码。
- 用户现场故障优先收集版本、日志、配置摘要、系统环境、启动命令和错误截图。
