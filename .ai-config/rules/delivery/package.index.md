# 打包与交付体检

本文件用于用户声明后的打包、部署、分发和交付验收体检。体检目标是用二八法则先确认产物能否在目标环境运行、能否被追溯、能否排障，以及是否存在密钥、依赖、资源和配置风险。

## 1. 二八体检顺序

按以下顺序检查：

1. 运行闭环：目标产物是否能在目标环境启动并跑通最小可用链路。
2. 依赖资源：代码依赖、静态资源、动态加载、浏览器 / 驱动 / 系统库是否随产物或说明交付。
3. 配置密钥：环境差异、密钥、账号、证书、URL、权限是否安全表达。
4. 版本追溯：产物能否定位版本、commit、构建时间、构建环境。
5. 分发说明：用户是否知道如何安装、启动、配置、查看日志和升级。
6. 现场排障：失败时是否能拿到日志、配置摘要、系统环境、错误截图和启动命令。

## 2. 交付级别判定

| 级别 | 判定 | 体检要求 |
|---|---|---|
| 试包验证 | 本机临时产物，仅用于验证打包命令或入口 | 运行一次产物或等价入口，并标明不是正式交付验证 |
| 正式交付 | 发给他人、测试 / 生产部署、客户现场、非开发机运行 | 运行闭环、依赖资源、配置、版本、分发清单、未验证项必须完整 |
| 高风险交付 | 生产配置、密钥、证书、安装器、服务注册、计划任务、数据迁移、覆盖用户文件 | 先确认环境、回滚、权限、验收路径和失败处理，再执行 |

## 3. 必查证据

| 体检项 | 必查证据 | 高风险信号 |
|---|---|---|
| 最小可用链路 | 启动命令、页面 / CLI / GUI / API 验证结果 | 本机能跑但目标环境未验证 |
| 依赖资源 | lock 文件、构建配置、资源目录、动态导入清单 | 缺模板、图标、浏览器、驱动、模型、系统库 |
| 配置密钥 | 配置样例、环境变量、启动参数、脱敏摘要 | 真实密钥随产物分发，环境差异靠改代码 |
| 版本追溯 | 版本号、commit、构建时间、构建环境 | 产物来源不可追踪，试包和正式版本混淆 |
| 分发说明 | 文件清单、启动方式、配置字段、日志位置、升级规则 | 只给 exe，缺 `_internal` 或资源目录 |
| 现场排障 | 日志、错误截图、系统环境、启动命令、配置摘要 | 用户现场失败无法复现和定位 |

## 4. 形态验收重点

| 交付形态 | 最小验收路径 |
|---|---|
| 桌面程序 | 主窗口打开、核心操作执行、资源加载、退出流程 |
| CLI | `--help` 可用、核心命令可跑、退出码合理、输出路径可写 |
| Web 服务 | 健康检查或根路径可访问、关键 API 正常、静态资源正常、配置加载正确 |
| HTML / 演示稿 | 入口可打开、核心页面或翻页路径可浏览、图片 / 字体 / 图表加载正常 |
| 浏览器自动化工具 | 浏览器可启动、登录或人工登录流程明确、关键页面可达、输出路径可写 |
| Docker / 服务部署 | 容器可启动、health check 通过、日志可查看、配置挂载路径正确 |

## 5. ROI 判定

| 优先级 | 判定 | 推荐动作 |
|---|---|---|
| P0 | 目标环境无法启动、密钥泄漏、资源缺失、配置不可用、生产回滚不明 | 先修复或暂停交付 |
| P1 | 影响安装、升级、排障、版本追溯或正式验收 | 补构建配置、说明、验证或日志 |
| P2 | 体积优化、说明细节、非关键自动化增强 | 记录边界，低成本时处理 |

## 6. 输出闭包

交付体检结论必须表格化，并包含：

- 最高风险的 1-3 个交付问题。
- 证据位置：构建配置、产物路径、启动命令、日志、截图、目标环境。
- 推荐处理：修复、补说明、补验证、延期或暂不处理。
- 未验证项：目标系统、目标平台、账号权限、网络、浏览器、生产配置。
