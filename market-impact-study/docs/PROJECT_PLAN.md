# 市值反应解释系统总体方案

## 1. 项目口径

推荐题目：

> 基于机器学习与稳健推断的上市公司市值反应解释系统：以移为通信及同行公司为例

本项目面向 CFO 市值管理决策。主线不是预测绝对市值或股价，而是解释和复现历史事件后的相对市值反应，并将结果转化为信息披露、投资者关系、资本动作和风险沟通建议。

| 原则 | 口径 |
| --- | --- |
| 研究对象 | 移为通信及同行公司 |
| 样本单位 | 公司 - 事件 - 交易窗口 |
| 主目标 | 解释和复现事件后相对同行的市值反应 |
| 非主目标 | 不承诺预测未来绝对市值，不把模型结果表述为严格因果 |
| 方法定位 | 机器学习用于复现和解释，稳健推断用于验证核心结论，CFO 建议用于业务落地 |

核心问题：

1. 移为通信及同行上市以来，市值变化经历了哪些阶段，关键事件是什么？
2. 财务、估值、交易、事件、管理层和竞品信号能解释多少事件后市值反应差异？
3. 哪些事件类型或管理层信号与正向重估、负向冲击稳定相关？
4. 模型解释结果能否转化为 CFO 可执行的披露、投关和风险沟通策略？

## 2. 研究设计

### 2.1 样本与事件

事件来源包括公告、业绩预告、业绩快报、定期报告、资本动作、机构调研、业绩说明会、互动问答、研报、新闻和竞品事件。

进入主报告前必须人工复核 Top 正负事件，尤其是流程型公告、同日多附件公告、交易异常、重复披露和自动分类为“其他”的事件。

### 2.2 标签

主标签使用事件后相对同行市值收益率：

> 事件后相对市值收益率 = 公司事件窗口市值收益率 - 同期剔除自身后的同行平均市值收益率

| 标签 | 用途 |
| --- | --- |
| `relative_mv_return_p0_p20` | 主标签，中期市值反应 |
| `relative_mv_return_p0_p5` | 短期反应稳健性 |
| `relative_mv_return_p0_p60` | 延迟反应稳健性 |
| `abnormal_mv_impact_yi` | CFO 展示用，换算为亿元 |

辅助分类标签可将主标签离散化为正向重估、中性反应、负向冲击，用于 CFO 风险预警和课程机器学习展示。

### 2.3 特征工程

所有特征必须满足 point-in-time 原则：特征可用日期 `as_of_date` 不得晚于事件日。

| 特征组 | CFO 逻辑 | 示例 |
| --- | --- | --- |
| 基本面质量 | 市值长期由盈利能力和现金流质量支撑 | 营收增速、净利增速、ROE、毛利率、经营现金流/净利润、资产负债率 |
| 估值状态 | 市场是否已经充分定价 | PE、PB、PS、市值分位数、估值相对同行分位数 |
| 交易情绪 | 市场关注度和短期资金行为 | 换手率、成交额、量比、过去 5/20 日收益、波动率 |
| 事件信号 | 信息披露对市场预期的冲击 | 事件类型、关键词强度、来源权重、是否有 PDF、是否高优先级事件 |
| 文本信号 | 公告和投关文本的语义强度 | TF-IDF、关键词词典、风险词、增长词、文本长度、数字密度 |
| 管理层信号 | CFO 可主动管理的信息沟通变量 | 调研频次、业绩说明会、互动问答数量、机构关注度、管理层关键词 |
| 竞品环境 | 控制行业共振和替代效应 | 同行收益、同行估值变化、同行事件密度、竞品同窗重大事件 |
| 市场状态 | 控制牛熊市、财报季和宏观周期 | 指数收益、年份、季度、财报窗口 |

特征质量要求：

- 每个特征有来源字段、计算口径和 `as_of_date`。
- 缺失值有明确处理策略。
- 极端值需 winsorize 或分位数截尾，并保留原始值以便审计。
- 绝对市值、成交额等规模变量优先转为收益率、分位数、对数或相对同行指标。
- 禁止使用事件后窗口内生成的信息作为特征。

## 3. 数据契约

详细计算过程、Oracle、模型评估和稳健性口径见 `docs/METHOD_AND_EVALUATION_PROTOCOL.md`。总体方案只保留核心原则，报告撰写时以该协议为准。

### 3.1 SSOT

| 表 | 内容 | 作用 |
| --- | --- | --- |
| `raw_manifest` | 来源、下载时间、股票代码、文件 hash | 追踪原始数据 |
| `event_master` | 事件 ID、公司、事件日、来源、类型、标题 | 统一事件样本 |
| `label_master` | 5/20/60 日相对市值收益率和异常市值影响 | 统一标签 |
| `feature_master` | 事件日前可用特征、来源、`as_of_date` | 统一特征仓 |
| `split_master` | train、valid、test 标记 | 固定切分 |
| `model_registry` | 特征列表、参数、随机种子、训练时间 | 复现实验 |
| `metrics_master` | 模型指标、分组指标、置信区间 | 统一评估 |
| `explain_master` | SHAP、Permutation、Top 特征排名 | 统一解释 |

### 3.2 Oracle 校验

Oracle 指机械可复算的权威口径：

| 对象 | Oracle |
| --- | --- |
| 市值变化 | 从 `daily_basic.total_mv` 按交易窗口独立复算 |
| 相对同行收益 | 公司市值收益率 - 剔除自身后的同行平均市值收益率 |
| 事件窗口 | 用交易日历对齐，不用自然日 |
| 财务特征 | 只取事件日前已披露的最近一期 |
| 模型指标 | 从 `y_true`、`y_pred`、`split` 自动计算 |

## 4. 模型与检验

### 4.1 模型结构

| 模型 | 作用 |
| --- | --- |
| Ridge / ElasticNet | 可解释基准模型，观察线性方向 |
| LightGBM / XGBoost | 主模型，复现非线性市值反应 |
| 三分类模型 | 辅助输出正向重估、中性、负向冲击概率 |
| 固定效应回归 | 解释核心事件类型与市值反应的稳健关系 |

训练策略：

- 采用时间切分，避免未来信息泄漏；示例为 2016-2022 训练，2023 验证，2024-2025 测试。
- 不使用随机切分作为主评估。
- 按公司、年份、事件类型做分组评估。
- 预测任务表述为“复现和解释历史市值反应”，不表述为“预测未来绝对市值”。

主评估指标：

| 任务 | 主指标 | 辅助指标 |
| --- | --- | --- |
| 回归主任务 | MAE、Spearman IC、out-of-sample R2 | RMSE、Directional Accuracy、分组 MAE |
| 分类辅助任务 | Macro F1、负向冲击 Recall | PR-AUC、Confusion Matrix、Brier Score、Calibration Curve |
| 消融实验 | test MAE 和 Spearman IC 的边际改善 | 分组表现、稳定性 |
| 稳健推断 | 系数方向、置信区间、WCB p 值 | 聚类口径敏感性 |

### 4.2 消融实验

消融实验按特征组逐步加入，用于证明特征工程的边际贡献：

1. 基本面 + 估值。
2. 加入交易情绪。
3. 加入事件信号。
4. 加入文本信号。
5. 加入管理层信号。
6. 加入竞品环境和市场状态。

### 4.3 黑箱与稳健性检测

| 风险 | 检测方式 |
| --- | --- |
| 数据泄漏 | `as_of_date <= event_date` 校验、时间切分、禁止未来窗口特征 |
| 过拟合 | train/valid/test 指标差异、学习曲线、时间外测试 |
| 事件污染 | 同公司同窗口事件重叠标记或剔除 |
| 类别不平衡 | Precision、Recall、F1、PR-AUC |
| 校准失真 | calibration curve、Brier score |
| 分组偏差 | 分公司、分年份、分事件类型评估 |
| 分布漂移 | PSI、KS、训练/测试特征分布对比 |
| 解释不稳定 | SHAP 与 permutation importance 对照 |
| 异常值驱动 | winsorize 前后对比、去除极端事件重跑 |

### 4.4 Wild Cluster Bootstrap

Wild Cluster Bootstrap 用于稳健推断，不替代机器学习模型评估。

推荐用途：

- 固定效应回归中检验事件类型、管理层信号、风险事件与相对市值反应之间的稳健关联。
- 在公司和时间维度存在相关性时，为核心系数提供更稳健的置信区间。
- 作为 CFO 结论背书，而不是证明严格因果。

建议表述：

> 在控制公司固定效应、年份或月份固定效应、市场状态和竞品表现后，采用聚类稳健标准误与 Wild Cluster Bootstrap 检验关键事件信号与市值反应之间的稳健关联。

注意：只有 9 家公司时，单纯按公司聚类的 cluster 数偏少，可考虑公司-年度、公司-季度、事件月份或双向聚类作为稳健性对照。

## 6. 十天执行计划

目标是在 10 天内交付主线完整、可复现、可展示、可写入简历的版本。前 4 天打牢数据和特征，第 5-8 天完成模型、解释和稳健性，第 9-10 天集中完成报告、PPT 和提交包。

| 天数 | 核心任务 | 关键产出 | 必须人工判断 |
| --- | --- | --- | --- |
| Day 1 | 数据拉取、目录整理、字段核对 | 数据清单、目录结构、字段字典 | 数据是否完整，哪些数据进入主线 |
| Day 2 | 构造标签和 Oracle 复算 | `label_master`、标签分布图、复算校验 | 主标签是否采用 20 日窗口，5/60 日是否作为稳健性 |
| Day 3 | 事件主表清洗和 Top 事件复核 | `event_master`、事件分类修正版、事件重叠污染图 | 哪些 Top 事件是真正有经济含义 |
| Day 4 | 结构化特征工程 | `feature_master`、缺失率图、特征分布图 | 哪些特征有财务理论依据，哪些应删除 |
| Day 5 | 轻量 NLP 特征和特征可视化 | TF-IDF/关键词特征、文本特征图、事件反应图 | NLP 特征是否可解释，是否引入噪声 |
| Day 6 | 建模 baseline 和主模型 | Ridge/ElasticNet、LightGBM/XGBoost 初版结果 | 模型是否服务解释和复现 |
| Day 7 | 模型评估和消融实验 | 时间外测试、消融图、分组表现、校准图 | 哪些结果稳定，哪些只能放附录 |
| Day 8 | 模型解释和稳健性检验 | SHAP、Permutation、WCB、误差复盘 | 哪些结论能写进主报告 |
| Day 9 | CFO 结论和报告初稿 | 报告主体、CFO 建议矩阵、关键图表 | CFO 建议是否有证据支撑 |
| Day 10 | PPT、README、提交包和口径复核 | PPT、报告、代码、数据、README、压缩包 | 表述是否统一，是否避免过度因果和预测承诺 |

### 6.1 必做与降级

| 类别 | 内容 |
| --- | --- |
| 最小合格版本 | 20 日相对市值收益率主标签；基本面、估值、交易、事件、竞品五组特征；线性 baseline + 树模型；时间外测试；消融实验；SHAP；固定效应回归；完整报告 |
